## 四、⚠️ 系统碰撞与解法（每条都要你认一下）

1. **视频号没有「号」可绑** → 解法：视频号这一格显示「登录态」（已登录 / 没登录 / 过期），不做绑定、不做换绑。后台发放页也不给它加换绑列。
2. **「每篇点暗」已经有了，别再造第二套** → 解法：总开关只做三件事——给新篇定默认、一键全跳过某家、在工作台顶部显示当前哪几家在干活。每篇的章照旧可点。
3. **执行器现在一次只干一单** → 解法：一篇在三家要发，拆成三条小单同时派；每家独立回执、独立失败，互不牵连。主单只负责汇总。
4. **干活窗的「整页锁」和「被人手碰过」的计数是按整扇窗算的** → 解法：改成按标签算；并行时只锁正在被机器人操作的那个标签，人手碰别的标签不算这一单的账。
5. **服务器派单和回执是一单一个平台** → 解法：保留「一单一个平台」不变，只增加「同一篇三条小单可以同时在飞」；工作台从一张主单读三条子单的进度。
6. **并行点击更密，风控更险** → 解法：同时在飞最多 2 家；两家之间随机错开几秒；一家失败立刻停那一家，不牵连另一家。
7. **视频号后台是 iframe 表单** → 解法：不动现有通路，只是把它从「轮到才跑」改成「可以同时跑」。
8. **小红书获客和小红书发布是同一个站** → 解法：加「同平台互斥」：同一个平台同一时刻只允许一单，哪怕一篇是获客、一篇是发布。

## 五、界面会长什么样（演示页照这个做）

- **发布队列顶部**：`📕 小红书 [亮]   🎵 抖音 [亮]   🎥 视频号 [灰·暂未接]`，点亮的两家点一下就暗；旁边一句：「点暗＝这家先不干活，所有篇都跳过；单篇还能在行里单独调」。
- **发布台每一篇**：保留现在的三颗平台章，但默认值来自上面的总开关。
- **工作台**：一篇一张卡，卡下每家一行：
  - 小红书 · 改稿中 → 传图 40% → 填字 → 发布中 → ✅ 已发
  - 抖音 · 开页面 → 传素材 60% → 等转码 → ⏳
  - 视频号 · 暂未接（灰行，不跑）
- **等您接手**：哪家要扫码 / 验证码 / 过目，就钉一条在那里，另两家照跑。
- **一键停**：「停这一趟」＝当前这篇三家都收尾就停，后面的篇不跑。

## 六、验收标准（怎么算做完）

1. 把「抖音」点暗 → 到点只有小红书跑，抖音不出现（视频号开关是灰的，点不动）。
2. 两家全亮发一篇视频 → 工作台两行**同时在动**，不是顺着来。
3. 中间把抖音那条卡住（比如故意不登录）→ 小红书照常发完，抖音标「等补发」。
4. 获客正在跑小红书时，发布不能同时抢小红书 → 排队或明确提示，不互相打断。
5. 一台机器同时最多 2 家在飞；视频号开关显示「暂未接」，这轮不接进开关和并行，它原来的发法照旧。
