## 一、评估：现在的发笔记为什么单薄

现状盘点（据 `extension/popup.js` / `background.js` / `lib/video/styles.js`）：

| 能力 | 现状 | 问题 |
|---|---|---|
| 向导产出 | 卖点→人群→话题→挑稿（这条线底下的几种写法同题各写一篇，点中哪篇就用哪篇）→成稿→出料，出一条成稿 + 两段出图提示词 / 一段口播稿 | 产出本身够用，**没有下半场** |
| 历史留存 | `_npWiz` 全在内存，关掉弹窗即蒸发 | 昨天写的那篇找不回来 |
| 持久化 | 只有 `np_used_topics`（500 条，防选题重复）+ 出片台 `xhsFilmScript/Style/Voice`（各一份，覆盖式） | 没有一个地方回答「我一共写过几篇、都发了没」 |
| 素材 | 无 | 每次配图都从零想；写完也不知道那几张图该去哪找 |
| 与 ⑤ 规划的关系 | 诊断⑤的 `note_plan`（内容方向 / 频次 / 时段 / 选题）已经存着 | **发笔记向导根本不读它**，规划与执行是断开的 |
| 发布之后 | 无 | 不知道发没发、发了几天、哪篇是图文哪篇是视频 |

一句话：**上半场（生产）完整，下半场（素材准备 + 留存 + 发完维护）是空的。** 用户拿到的是一篇文本，不是一个"号在持续运营"的感觉。

## 二、大类汇总

**两个维度**：一条笔记的「产品形态」决定出口，「表现形式」决定它长什么样、要什么素材。

### 2.1 产品形态（＝做料路线，按平台给）

| 平台 | 出口 | 需要的输入 |
|---|---|---|
| 📕 小红书 | 📝 图文 ／ 🎬 视频 | 成稿 + 一张**画面表**（一句＝一张画面，按画面号各出一条出图提示词；图拿去外部出图工具生成，再按画面号传回素材库）／ 成稿 + 口播稿（这一档先定成片形式：PPT字体动效 / 卡片画面叙事 在本机出片台出片） |
| 🎵 抖音 · ⚡ 快手 | 🎬 视频（主推）／ 📝 图文 | 口播稿 → 出片台出 9:16 竖版成片；图文同样走画面表（一屏一句大字，张数跟着断句走） |
| 🐟 闲鱼 | 📝 商品帖图（只有这一条） | 成稿 + 画面表按号出的**主图 / 详情图**提示词（同一套流程，只是称呼换掉），配合标题与描述一起上架 |

> 做料路与形式**按平台收口**（真源 `extension/lib/platforms.js` 的 `PATHS` / `STYLES`）：小红书 图文+视频、抖音/快手 视频优先+图文、闲鱼 只有商品帖。`STYLES` 里图文那几种仍在用；**视频那两种（口播讲解 / 卡片轮播口播）自五十二改起不再是选项**，只作为喂 AI 的写法口径由成片形式派生（见 §2.2）。
> **2026-09-30 四十八改起改了口径**：平台不再在 ① 先选（写稿一路按 📕 小红书口径）——到 ⑤ 成稿页勾「这条发到哪些平台（可多选、默认小红书）」，定稿时其余勾的平台**各自动改写一版、各成一档**（📕 版＝手上原稿），⑥ 出料页顶部一条版本条切版出料；漏勾的可「↗ 同一篇，再补一个平台的版本」。档案侧原来的「派生到别的平台」入口仍在（见 §八 与 §十三）。**（五十二改后这句要更正：页面已改名——⑤ 成稿页＝⑤ 改稿页、⑥ 出料页＝⑥ 发稿页；「补一个平台的版本」只剩发稿页版本条那一个入口，档案那一行不再另摆派生按钮。）**

### 2.2 表现形式（＝内容结构，按平台各一套）

**图文这一头分两层**（五十二改）：

**A. 这一套图整体怎么做**（`Platforms.STYLES[基座].image`，在「🖼 图文做哪一种」那排选；抖音/快手也是这 4 种，但按 9:16 一屏一句/一屏一步写；闲鱼换成「服务介绍式 / 案例展示式」2 种——主图写清提供什么、详情图讲交付流程与适合谁 / 摆过程与对比）

| 形式 | 长什么样 | 素材依赖 |
|---|---|---|
| 清单卡片式 | 1234 条并列，一条一屏，数字/短句打头 | 弱——底色 + 大字即可 |
| 教程步骤式 | 第一步…第二步…，配过程画面 | **强——步骤图 / 操作截图** |
| 对比测评式 | 前后 / 新旧 / AB 对着看 | **强——对比图**（自己前后、工具截图） |
| 经验故事式 | 叙事口吻，情绪打底 | 中——氛围图 / 场景图 |

**B. 每一张画面怎么做**（`NP_SHOT_FORMS`＝**对比 / 故事场景 / 事物评价 / 清单要点 / 金句大字**，在画面表里一行一画面各选各的）：✂️ 断句之后**一句正文＝一张画面**，这一张的形式与「画面上摆什么」各定各的，过场话可标「不占图」，全篇再共用一份统一风格 + 一份封面提示词。这一层解决的是旧版那个毛病——图和文案没有时间线关系（还在讲第一句就已经播第二句的图）。

**视频这一头＝五种「成片形式」**（`NP_FILM_KINDS`：出片台第一步与造图片页视频那一排读同一份真源，**一篇只定一个**，选完落档案 `np_notes[].filmKind`）

| 成片形式 | 在哪出片 | 料从哪来 |
|---|---|---|
| PPT字体动效 | **这台电脑上**（出片台：口播稿 → 分幕 → 配音 → 出片，出完下载） | 一句话一屏大字 + 配音，不用备图 |
| 卡片画面叙事 | **这台电脑上** | 底图跟着「🖼 造图片」那张画面表走：张数＝幕数时第 N 幕安第 N 张画面传回来的图，没传图的幕走纯色卡；对不上就退回按素材库顺序铺并在状态栏说一句。台子上的「⑤ 卡片底图」也带图片叙事（AI 排「第几幕起换哪张图」，同图连着的几幕卡不翻、只在卡里换字） |
| 动态视频 | 第三方（把画面那批图逐张丢豆包 / 千问变成会动的，再拼一条；按那边的额度跑） | 扩展给整段口播稿 + 那份画面表 + 教程（拆 4~6 个分镜 → 逐镜图生视频 → 剪映拼） |
| 实拍 | 用户自己出镜 | 扩展给口播稿 + 怎么拍 + 字幕那份教程 |
| 数字人 | 第三方（即梦数字人 / 对口型） | 扩展给**整段连续**口播稿（不是分幕稿）+ 字幕那份教程 |

> **旧的「视频 2 种表现形式」去哪了**：口播讲解 / 卡片轮播口播不再是用户选项，只作为**喂 AI 的写法口径**由成片形式派生——`NP_KIND_VIDEO_STYLE`＝PPT字体动效→口播讲解、卡片画面叙事→卡片轮播口播（`npStyleOf(w,'video')`），口播稿提示词、那一份教程和档案「表现形式」那一列仍读这两个名字。老档只记过 `style`、没记过 `filmKind` 的，读的时候按旧名反推（`npKindFromLegacy()`），**不迁数据**。
> 录屏演示、素材混剪**不出片**，只出一份「分镜清单」（第几秒拍什么、录什么）交用户自己剪——符合"插件不碰用户屏幕录制"的边界。

### 2.3 素材需求的三层来源

这是素材库"该存什么"的答案，不是拍脑袋定类目：

1. **卖点层** —— 产品要展示的东西（界面截图、功能演示图、前后对比）
2. **知识库层** —— 知识库里提到、需要图证的东西（政策截图、数据图、流程图）
3. **表现形式层** —— 形式自带的固定需求（教程式→步骤图；对比式→对比图；故事式→氛围图）

## 三、四个板块

### A. 素材库：需求驱动，不是空仓库

用户不知道该传什么图——所以**先算需求，再让他去备**。

**2026-09-25 收敛（二十七改）：整页就是「一张表 + 两个按钮」**，设计语言＝**AI 告诉我要什么，我准备什么**：

| 元素 | 是什么 |
|---|---|
| **🤖 AI 整理素材**（主按钮） | 按 **卖点 × 知识库 × 表现形式** 经 AI 出一份「要备哪些图」的清单（`genAssetNeeds`），写进 `np_asset_needs`。这是表内容的唯一来源，也是唯一的重算口 |
| **➕ 新增素材**（按钮 → 弹窗） | 手上已经有图时用：**素材说明必填**（用户自己写）+ 选本机图，存下去由 **AI 按这句说明关联 知识库 × 卖点**（后台 `assocAsset`）；没关联上就在行里给「🔗 关联」重试 |
| **表格（5 列）** | 素材 ｜ 要什么·说明 ｜ 来源·关联 ｜ 进度·用在哪 ｜ 操作 |

⚠ **表格这个看法两天里又改了两趟**（同日二十八改 → 二十九改）：**现在是一条素材一张卡**（见 §四 线框图）——5 列表格在 640px 弹窗里挤得看不见字；`📋 复制` 也已撤，「要有 N 张 · 已有 M 张 ｜ 用在哪」并进标题行。**字段与两个按钮不变，只换了看法**；上表那三列在卡里对应的位置见 §四。

- `np_asset_needs`（清单）：每条＝ `{ id, title（名目，含数量如「产品界面截图 ×2」）, spec（要什么：内容 + 画面要求）, source（来源名，原样抄卖点 / 知识库条目 / 六种形式之一）, manual（是不是我自己加的）, createdAt }`
- `np_assets`（实际素材）：**只存引用 + ≤160px 缩略图**（拍板②）
- 两态是**推出来的**，不单独存：`待备`（挂上的不够数）／`已有`（够数了）；名目里写了 `×N`／`N 张` 就按 N 算。「用在哪」同样在渲染时按 卖点 / 知识库 / 表现形式 对照档案现算（对得上就点那篇的标题，没人用过就老实写「还没用在笔记上」）
- **不重复烧 AI**：`signature`（产品名 + 卖点标题 + 知识库标题）没变就不重算；重算保住自己手动加的那几条
- **已有配图自动认领**：来源指向的卖点 / 知识库条目里本来就有图（`sellPoints[].image` / 条目 `image`），渲染时直接算作「已有」，只记名字现取——库里换图，素材库跟着变
- 行里只剩两个动作：**📁 传本机图**、**×**（从表里删；再点 AI 整理会回来）

**已下线（2026-09-25 二十七改）**：`🔗 贴链接`、`✓ 备好了 / 不需要` 三态标记与四枚筛选、`➕ 自己加一条需求`、`📋 复制「要什么」` 的独立位（复制动作并进「要什么」那一格）——老板原话「不要贴链接的功能了。就留一个传本机图的入口就好了」「不需要的按钮应该也是没用的吧？去掉吧」。**别再按老稿把它们加回来**。（其中并进「要什么」那一格的 `📋 复制`，**二十九改也整条撤了**——要看「要什么」自己框选。）

**素材只存引用 + 分层缩略图**（拍板②+⑥）：

| 素材来源 | 存什么 | 体积 |
|---|---|---|
| 知识库内的图 | 只存引用（名字 → 现取），显示时现取 | 0 |
| 本机文件 | 存引用 + **≤160px 缩略图**（base64 jpeg）+ 文件名 | ≈10~20KB / 张 |

原图**不入库**：手机实拍一张 2~5MB，几十张就是几百 MB；`storage.local` 虽有 `unlimitedStorage` 名额，但它是**整键 JSON 读写**——原图会让每次读写变慢、加密备份也跟着炸。原图由用户自己保管，库里靠**缩略图 + 文件名**对照。缩略图不只是省地方，它正是老板要的"看得见系统干了啥"（本机图 480×360 / 900×1600 传进去，压成 160×120 / 160×160 再存，自检里盯死这一点）。

### C. 归档的消费点：缺口提示

档案列表每条显示「**这篇还缺 2 张**（教程步骤图 ×2）」——点进去直接补素材。
这个小钩子把**素材库**和**笔记档案**连成一条线：归档不是死记账，它反过来告诉你下一步该备什么。

### D. 与「规划」页的关系

`note_plan`（内容方向 / 频次 / 时段 / 选题）是「规划」页的产物，向导本身不读它；档案页**只读**它的一句「发布频率」，在筛选条下面显示一行灰字（📅 本周已发 N 篇 · 规划每周 N 篇），**只提示、不约束**——不卡发布、不改向导，点这行落到「规划」页改。

## 五、数据键与备份口径

| 键 | 内容 | 进加密备份？ | 理由 |
|---|---|---|---|
| `np_notes` | 笔记档案（含成稿全文） | ✅ 进 | 用户核心资产，300 篇 ≈ <1MB |
