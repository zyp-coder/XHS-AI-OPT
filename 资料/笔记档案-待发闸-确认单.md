# 笔记档案：「待发」＝真能发 · 确认单

> 2026-10-26 老板定的七条（全按推荐档）。状态：本机主本开发中，未推公网。

## 一、要解决什么

现在档案里标「代发」只是换个标签，稿子/图/片没齐也能标；到发布台点「🚀 发布」才被弹「还缺料」。这个状态没有意义。

改成：**标「待发」＝这篇现在就能在发布台直接发出去**，不齐就标不上，并当场说清缺哪一样。

## 二、七条口径

| # | 事项 | 定的 |
|---|---|---|
| 1 | 状态叫什么 | 界面统一叫「**待发**」（库里仍存「代发」，老数据不用迁；服务端本来就两个词都认） |
| 2 | 「全做完」＝哪几样 | ① 稿：标题＋正文成稿；② 图/片：图文＝封面＋配图齐，视频＝一条成片；③ 料已进发布台那份（实际要上传的副本） |
| 3 | 没做完时标待发 | **硬拦**：标不上，弹一句说清缺什么 |
| 4 | 自己传的图算不算齐 | **算**：标待发时先自动把档案里那套图搬进发布台（服务器出的取原图，自己传的取本机 1080 预览图），搬齐就通过 |
| 5 | 视频篇的「片」 | 一条能发的成片（自己传的整条、字效编辑器出的、云端取回的，都算） |
| 6 | 存量：已标待发但缺料 | **自动退回草稿**，并在档案行里标出缺什么 |
| 7 | 档案里怎么提示 | **行内小标**（「✓ 料齐 · 可待发」／「⚠ 还没有发布用的图」）＋**页面顶上一条汇总**（「还有 N 篇没做完」） |

## 三、落在哪（都只动 `web/popup.js`）

| 位置 | 改什么 |
|---|---|
| 发布料那一块 | 新增「齐不齐」判定（稿／长文免图／图文要图／视频要片）＋「从档案搬料」 |
| 状态写入 `npNoteSetStatus` | 标待发先判定；不齐先自动搬一次，仍不齐就拦下并说明 |
| 写稿自动推进 | 定稿自动往前推待发时同样判定；不齐就留在草稿（不再空标） |
| 批量载入发布队列 | 缺料的篇照样排位子，但**不标待发**，并提示几篇缺料 |
| 档案页渲染 | 存量缺料的待发篇退回草稿；每行加料小标；顶上加汇总条 |
| 状态文案 | 筛选条、下拉、批量条、提示语里的「代发」→「待发」 |

不改：服务器、执行器、发布台的发布链。发布台那道「缺料」闸保留作双保险。

## 四、验收（怎么算做完）

1. 档案里一篇图文，有稿没图 → 下拉选「待发」：标不上，弹「还没有发布用的图」。
2. 同一篇，图已在档案里（服务器出的或自己传的）→ 选「待发」：自动搬进发布台，标上「待发」，行里显示「✓ 料齐 · 可待发」。
3. 到发布台点「🚀 发布」：直接开选家小窗，不再弹缺料。
4. 视频篇只有分镜没成片 → 标不上，提示缺成片。
5. 长文篇 → 不需要图，直接能标。
6. 原来标着「代发」但缺料的存量篇 → 打开档案自动变回「草稿」，行里红字写缺什么。
7. 页面顶上：「还有 N 篇没做完」只数「有稿但缺料」的，不数空稿。
8. 批量载入发布队列：缺料的篇排上位子但状态仍是草稿，提示里说明几篇缺料。

## 五、没做的（记着）

- 发布台「缺料」提示保留，但没有再触发的正常路径（双保险）。
- 执行器、服务器、另外两份副本（`extension/`、`executor/`）这轮不跟。

## 七、修（2026-10-26 12:30）：误退草稿 + 「有片说没片」

### 病根（两条，都是 11:59 那版的漏洞）

1. **成片不在发布台那份料里。** 视频篇的成片存在本机档案仓 `film:<篇id>`（「成片预览」读的就是它），
   发布台读的是另一份 `np_pub_files`（`pub:<篇id>:0`）。判定只看了后者，所以「片明明能看、却说没有成片」。
2. **退回不搬就退。** 档案页一打开就把料没进发布台的「待发」篇退回草稿，**不看档案里有没有图 / 有没有片**。
   于是带图带片的也一起被退成草稿，老板又找不到补的办法。

### 改法（只改 `web/popup.js`）

| 处 | 改了什么 |
|---|---|
| 判定 `npPubReadySync(n, files, film)` | 视频篇多认一个「档案里有成片」；没料但**有片**时说「片在档案里 · 标待发时自动搬进发布台」，不再说「还没有成片」 |
| `npPubReadyOf` | 判定前先看一眼 `film:<篇id>` |
| `npPubStageFromArchive` | 视频篇把那条成片搬进发布台（`npPubStageFiles(..., true)`）；图文搬图不变 |
| 标状态 `npNoteSetStatus` | 搬成功的提示分「那条成片 / 这套图」；搬不成就把搬料失败的原因说出来 |
| 退回 `npArRetreatUnready` | **先搬再退**：缺的只是「料没进发布台」就先搬一次（每篇每次会话只试一次），搬完还齐不了才退 |
| 恢复 `npArRestoreGateOnce` | **一次性**把「草稿 + 曾标过待发 + 现在料齐」的篇标回「待发」（顺手把料搬进发布台）；落库标记 `np_gate_fix_v1`，只跑一次，以后手动改回草稿不会被弹回去 |
| 档案页 | 画之前先认成片（只看草稿 / 待发的视频篇）；判定带上成片；画完再补跑一次恢复，搬完自动重画 |
| 行内小标 | 「图 / 片还在档案 · 标待发时自动搬」用**黄字**（还能补），真缺料才是红字 |
| 批量载入队列 | 判定也带上成片，有片的视频篇能顺手标「待发」 |
