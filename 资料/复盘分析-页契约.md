## 二、页签 ① · 选题盘点与规划

### 2.1 形态（二十三改落地：按知识库类汇总的 5 列大表）

「默认」类有条时表顶出一条黄底提示：「⚠ 还有 N 条归在「默认」类（多半是老档没归类）。点 诊断&配置 → 知识库，点 🤖 AI 批量归类 一键归到 8 类。」

```
┌─ 知识库类 ────┬─ 总条目 ─┬─ 还差 ─┬─ 结论 · 行末查 ──┬─ 表现 ────────────┐
│ 防水验收       │    5     │   2   │ 🟨 有空白 + 有表现 │ 已发 2 篇 · 日均赞 ≈87 │
│ 基层处理       │    4     │   0   │ 🟩 全讲过         │ 已发 1 篇 · 日均赞 ≈42 │
│ 避坑经验       │    6     │   6   │ 🟥 全空白         │ 还没发过           │
│ ⚠ 默认 待归类  │    3     │   1   │ 🟧 待归类         │ —                  │
└────────────────┴──────────┴───────┴───────────────────┴────────────────────┘
  └─ 「有空白 + 有表现」的类行下挂一条子行：
     还没写过：[国标卷材和非标差在哪] [防水验收要注意哪几处] … 等 2 条   ← 点条目开弹层并高亮
```

- 列宽：知识库类（弹性）｜总条目 80px｜还差 80px｜结论 200px｜表现 170px
- 「还差」列 = 该类没写过的条数（>0 红色，=0 灰）
- 点类行 / 子行条目 chip = 弹这一类清单（见 2.4）；表尾一行提示：「点行／点条目 → 这一类的清单列出来；勾上挑一篇发笔记用。」
- 排序：全空白 → 有空白 + 有表现 → 全讲过 → 空类（不显示）；同档按类名拼音

### 2.2 结论列四档（按 npAuditTopicsAlgo() 算，行悬停 tip 逐字如下）

| 档 | chip | 悬停 tip |
|---|---|---|
| 全空白 | 🟥 全空白 | 这一类里所有条目都没写过 —— 有料没用上，挑几条加进下次规划 |
| 有空白 + 有表现 | 🟨 有空白 + 有表现 | 部分讲过 —— 「还差」列里点进去看具体哪些没写 |
| 全讲过 | 🟩 全讲过 | 这一类里所有条目都写过 —— 可以换个角度写、或者先停一停 |
| 待归类（「默认」类专档） | 🟧 待归类 | 这一类大多是老档没归类——点「诊断&配置 → 知识库」用 🤖 AI 批量归类一键处理 |

- 「默认」类行名后还挂一枚小字「⚠ 待归类」；该类有条时表顶出黄底条（见 2.1）
- 分档只看三样：该类总条目 N、覆盖过 N、没写过 N（见 §四）；「表现」只影响显示、不影响分档

### 2.3 字段表（按 npUsageByKbCat() / npAuditTopicsAlgo() 落地）

| 字段 | 来源 | 算法 |
|---|---|---|
| 知识库类名 | knowledge_entries 的 `category`（兼容 `cat`），都没有归「默认」 | npUsageByKbCat() |
| 该类总条目 | entries where category=xx 且 `isActive !== false`（停用 / 删掉的不进） | 直接数 |
| 该类覆盖过 N | np_notes 的 kb[] 按 id 优先 / title 兜底命中该类条目（canonical key = id ‖ title） | coveredIds（Set） |
| 该类没写过 N | 该类条目 - coveredIds（同一篇不重复计） | 差集 = 「还差」列（>0 红、=0 灰） |
| 结论四档 | 按 covered / blank 算（见 2.2 表）；「默认」类覆写为 🟧 待归类 | npAuditTopicsAlgo() |
| 表现 · 「已发 N 篇」 | 该类条目里被「已发 / 已归档」笔记写过的（已发优先、先到先得） | pubNoteByKey.size |
| 表现 · 日均赞 | 各已发篇 likes ÷ max(1, 发布天数)，取平均 | **均值（敲定）；中位数不做** |
| 表现 · 四档 | pub=0「还没发过」/ 没抓过主页「—」/ 没读到「已发 N 篇 · 表现还没读到」/ 有数「已发 N 篇 · 日均赞 ≈X」 | statsFetched + avgDay |
| 子行「还没写过」 | blankIds 前 8 条 + 「… 等 N 条」 | 点条目开弹层带高亮 |

### 2.4 操作（弹层 npAuditOpenCat；写回 npAuditPlanPush）

| 控件 | 行为 |
|---|---|
| 类行 / 子行条目 chip click | 弹这一类清单（modal）：已写过（N 篇）+ 还没写过（N 条）；从 chip 进来的高亮那一条 |
| 「还没写过」旁的 ☐ | 勾选维护 _npAuditPick（按标题）；底部按钮文案跟着变「（已勾 N 条）」 |
| 已被排过的条目 | 不给勾选框，挂「📅 已排 周X」徽（NotePlan.columnDayName(day)） |
| 「➕ 加进下次规划」 | 弹 picker——见 §2.6（把这条目直接挂到一篇草稿/代发的档案上） |
| 弹层底「📅 排进本周计划（已勾 N 条）」 | npAuditPlanPush()：逐条追加进 note_plan.items——`{no, title, type:'howto', day, done:false}`；day = 本周排法带「知识」的日子轮着排（没有落周一）；按标题去重；写回后 toast「已把 N 条排进本周计划——写回排产表了」+ 重开弹层（新排的挂上「📅 已排」徽） |
| 弹层里点「已写过」篇的标题 | 关弹层 + 切笔记档案 + 聚焦这篇（window._npArchiveFocus） |
| 弹层里点空白处 | 关弹层 |

### 2.5 空态文案（逐字照落地）

- 知识库空：「还没在「诊断&配置 → 知识库」录入条目。先去录入，再回来看盘点。」
- 没有可盘点的类（全空类）：「知识库当前没有可盘点的条目。」
- 「默认」类有 N 条（表顶黄底条）：「⚠ 还有 N 条归在「默认」类（多半是老档没归类）。点 诊断&配置 → 知识库，点 🤖 AI 批量归类 一键归到 8 类。」
- 没抓过主页：「表现」列显示「—」+ tip「点赞是抓主页顺带读的——先抓一次才有」（不报错）

### 2.6 「➕ 加进下次规划」picker（B12，2026-10-08 加）

「还没写过」列表里每条空白右边挂一颗 `➕ 加进下次规划`（淡红边描按钮）——点了不勾选池、而是**就地弹 picker**：

```
┌─ 防水验收 · 「国标卷材和非标差在哪」───────────────┐
│ ➕ 把这条知识挂到哪一篇档案的「知识库引用」？         │
│   ┌──────────────────────────────────────────────┐ │
│   │ (草稿) 防水卷材选购指南                [点选] │ │
│   │ (草稿) 卫生间漏水维修笔记              [点选] │ │
│   │ (代发) 屋顶防水施工流程                [点选] │ │
│   └──────────────────────────────────────────────┘ │
│                            [取消]                   │
└──────────────────────────────────────────────────────┘
```

- **候选池** = 当前 `np_notes` 里所有 `status ∈ {草稿, 代发}` 的档案，按 `title` 升序排（localeCompare `'zh-Hans-CN'`）
- **空态**：还没有草稿/代发档案 → picker 内一句「还没有草稿/代发的档案可挑——先去「发笔记 → 档案」建一篇草稿。」 + 不出候选
- **写入规则**：点某条候选 → 调 `npNoteAddKb(noteId, { id, title, cat })`（契约见 `资料/发笔记-数据契约补丁.md` §4.4）→ 成功显示「✅ 已挂到「xxx」」+ 900ms 后重开该类弹层并高亮这条（那条空白从「还没写过」消失）
- **重复挂**：同一条知识已在该档案的 `kb[]` 里 → 追加「（这条知识之前已挂过，不重复加）」，但仍算成功
- **不写入排产表**：picker 是把条目**已经存在**的档案挂上知识引用，与 2.4 的「📅 排进本周计划」是两件事——后者才写 `note_plan.items`
- **不自动跳档案**：写完留在弹层（重开的是这一类清单、不是跳档案），要看那一篇点「已写过」列表里的标题切笔记档案并聚焦

—— 实现位置：`extension/popup.js` `npAuditOpenCat()`（7660 行起）+ `npNoteAddKb()`（11789 行起）；demo 落点：`tmp/三方向demo.html` v-audit 页同类弹层。

## 四、知识盘点算法（B12）

### 4.1 入口（按落地）

```js
// ① 汇总：按知识库分类收条目 + 算档案覆盖（npUsageByKbCat，popup.js:7438）
//    → Map<cat, { catTitle, allItems[{id,title}], coveredIds:Set, blankIds:Set, pubNoteByKey:Map }>
//    「默认」类预置空桶；entries 过滤 isActive !== false；
//    覆盖命中 id 优先、title 兜底（canonical key = id ‖ title，同一篇不重复计）；
//    pubNoteByKey：只记「已发 / 已归档」的笔记（已发优先、先到先得）

// ② 结论 + 表现：npAuditTopicsAlgo（popup.js:7484）
//    conclusion：total=0 → '空类'；covered=0 → '全空白'；blank=0 → '全讲过'；否则 '有空白 + 有表现'
//    avgDay = 各已发篇 likes ÷ max(1, floor((now - sentAt) / 86400e3)) 的【平均】（没读到 → null）
//    数组上挂 statsFetched（抓过主页没有 → 表现列第二档「—」用）
//    排序：全空白(0) → 有空白+有表现(1) → 全讲过(2) → 空类(3，不渲染)；同档按类名 localeCompare('zh-Hans-CN')
```

### 4.2 数据流约束

- 三态口径按档案推（沿用二十改 #2）—— 没另存
- 「没写过」= 没在任何一篇的 `kb[]` 里出现过（id 优先 / title 兜底）
- 「已发 N 篇」（表现）= 该类条目里被 `status ∈ {已发, 已归档}` 的笔记写过的（已发优先、先到先得）
- 类级日均赞 = 各已发篇 dayAvg 的**平均**（#10 敲定；中位数不做）
- 不存快照：每次进页 / 切页签现算（档案 / 知识库 / stats 变了跟着变）

### 4.3 算法要避的坑

| 坑 | 怎么避 |
|---|---|
| 知识条目没分类（category 空） | 归「默认」类（🟧 待归类 chip + 表顶黄底条），不丢 |
| 类内条目 0 条 | conclusion='空类'，不渲染该行；整页没有任何可盘点的类 → 出空态 |
| 类内日均赞全 null（没抓过主页 / 没读到） | 表现列走第二 / 第三档（「—」/「表现还没读到」），不报错 |
| 同一篇 kb[] 里 id 和 title 都挂同一条 | canonical key 用 id 优先 title 兜底，coveredIds 是 Set，不算重 |
| 条目停用 / 删除 | entries 过滤 `isActive !== false`，不进盘点 |
| 知识库新增 / 删除条目 | 不缓存，每次现算（npUsageByKbCat 全量重扫） |
