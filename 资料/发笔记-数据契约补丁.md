## 一、A2 · 周排 / 发布台（队列＋自动排位子）

### 1.1 周排 `config.weekPlan`

```js
// 周一到周日，值是数组（多选）；空=休
config.weekPlan = {
  mon: [], tue: [], wed: [], thu: ['知识', '引流'],
  fri: ['引流'], sat: ['知识'], sun: []
}
```

- 真源 key：`config.weekPlan`（随其他 cfg 一起存 readConfigPlain 那一支）
- 口径：勾「知识 / 引流 / 案例」三选多；空数组=休
- 写入时机：任务配置页 `planWeek(day, k)` toggle；只更新这一格的数组
- 迁移：老档 `weekPlan = { mon: 'k', tue: 'd', ... }`（单值字符串）→ 读时 `Array.isArray(x) ? x : [x]`

### 1.2 发布队列 `config.queue`（发布台 · 📅 发布队列签，独立 key）

```js
// 键＝第几周:周几:基调，值＝篇 id 数组（同一格可排多篇）
config.queue = {
  'w1:thu:知识': [6],
  'w1:fri:引流': [9],
  'w2:mon:知识': [1],
  'w2:tue:引流': [2],
}
```

- 真源 key：`note_queue`（chrome.storage.local 独立 key，不并 cfg）
- 写入时机：发布台 · 📅 发布队列签 `qPick / qDrop`；**自动排位子 `npAutoPlaceNote`**（二十八改 2026-10-09）也往这里写——篇标「代发」那一刻按方向找最早的未来同类空位 append（幂等：已在任何位子上＝不动；没空位/没方向不写、落「🆕 写好等排期」）
- 渲染：qRows() 从 `weekPlan` × `queue` 长出来；改 weekPlan → 格子跟着长
- 周次算法：`nextMon = ((1 - tIdx + 7) % 7) || 7`（tIdx = today.getDay()）；第 1 周从今天到这周日，第 2/3 周从下一个周一起
- 排进篇：候选 = `rows.filter(r => (r.status === '草稿' || r.status === '代发') && !queued(r.id))`
- 删除篇：splice（qNotesOf 返回活引用要小心，见二十一改备注）
- 排产表条 `r.dir` 与基调 `kind` 关系：k=知识 / d=引流 / c=案例；写时统一大写首字

### 1.3 多产品切档

`config` / `note_queue` 都按 `tenant.<id>.` 前缀切档。切换租户时：
- 顶栏切 → 把当前内存里改过未存的改完写回当前租户
- 切到新租户 → 读新租户那份，未设值=空表（不是空对象）

### 4.4 档案 `kb[]` 追加契约（`npNoteAddKb`，B12）

复盘分析页「还没写过」条目旁边的 **➕ 加进下次规划** 按钮 → 弹 picker → 把一条知识库条目挂到指定档案的 `kb[]` 数组里。唯一入口函数：

```js
async function npNoteAddKb(noteId, kbItem)
// 入参：noteId = 目标档案 id；kbItem = { id: string, title: string, cat?: string }
// 出参：{ ok: bool, added?: bool, noteId, why?: string }
```

| 情况 | 行为 |
|---|---|
| `noteId` 或 `kbItem.id` 空 | `{ ok: false, why: '参数不全' }`，不写 |
| 档案 id 不存在 | `{ ok: false, why: '档案不存在' }`，不写 |
| 同 id 已挂 | `{ ok: true, added: false, noteId }`，不重复加 |
| 正常 | 在 `prev.kb` 后 concat `{ id, title, cat }`，`updatedAt = Date.now()`，写 `NP_NOTES_KEY`，返回 `{ ok: true, added: true, noteId }` |
| 写 `chrome.storage.local` 抛错 | `{ ok: false, why: '写入失败' }` |

—— **写入序列**走 `npNotesSync()` 串行链，避免和 `npNotesAll / npArchiveSave / npNoteSetStatus` 并发打架；**id 去重**用 `===` 字符串比较（同一条知识不重复挂）；`title` 与 `cat` 原样落，留作后续按 title 关联 / 类内统计的回退字段（`资料/笔记档案-数据契约.md` §1.1 把 `kb` 标成 `{id, title}[]`——`cat` 是 B12 之后才加的，schema 升级时回填即可）。

—— 调用方：复盘分析「➕ 加进下次规划」picker（见 `资料/复盘分析-页契约.md` §2.6）；后续若档案详情页加「➕ 挂知识」入口，复用同一函数。
