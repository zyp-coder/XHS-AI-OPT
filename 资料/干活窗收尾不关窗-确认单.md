# 干活窗收尾不关窗（2026-10-23 老板圈定）

## 要解决的事

老板在自己 Edge 上跑了一趟「搜索」：机器人干完，那扇干活窗 3 秒后就没了。他要看的结果页、想接着手点的那一页，跟着窗一起消失——「那怎么玩呢」。

根子一句话：`executor/exec-workwin.js` 收尾那句 `closeAfter(3000)`（跑完 3 秒关窗）。

## ✅ 已定（老板 2026-10-23：「按推荐方案改，完成后别关窗」）

1. **做完就停在那儿**：这一趟收尾**不关窗**。窗一直留着，直到他自己按 × 关掉、或关浏览器。
2. **哪些活停住**：凡是会在那扇窗里看得见页面的活都停住——发笔记、批量发、出片、获客那几门单步（搜索 / 截流扫一轮 / 补开 / 打开一篇 / 刷新）、日常浏览。压根不开窗的（写稿、出图、线索整理、自检）本来就没窗，不动。
3. **停住那一刻把页面交回给他**：平台页上的整页锁撤掉，顶上留一条「这趟完了 · 页面交给你，接着点没人管」；失败变橙条「这趟停在半路 · 页面留着给你看」。工作台那一页的大遮罩同步收成一条不挡点的顶条。
4. **下一趟来了复用同一扇窗**：不重开、不堆窗——上一趟机器人自己开的那几页收掉（他自己另开/另点的页不动），新页在这扇窗里接着开。
5. **面板那行字跟着说**：这一趟完了不再写「待命」，写「这趟完了 · 干活窗还开着（页面交给你）」。

## 📌 替你按默认定的

- **登录过期那条线不动**：还是留窗等你扫码、最多 10 分钟，扫码成功后窗自动收（那一单已经按失败回报过，人回工作台重新点开始）。只有这一种收尾还关窗。
- **人工处理（验证码）超时 5 分钟**：原来「重新上锁＋关窗」，现在改成「页面交给你＋橙条，不关窗」——关窗就没得看了，跟这次要解决的毛病是同一个。
- **他手动关掉这扇窗**：这一单已经回报完了，不再按失败算（现有逻辑本来就这样，不动）。
- **扩展重新加载／浏览器重开**：上一趟留着没人收的窗会被清掉（现有「启动清场」，保留）；这不影响「跑完不关窗」，只影响电脑重启后。

## 🚫 明确不做

- 不改「用哪扇窗干活」：还是同一个 Edge、同一份登录，不另起浏览器、不改窗口形态（老板问的「是不是内置浏览器」＝是，答案在对话里，不进代码）。
- 不改整页锁的挡法（只挡人手 `isTrusted`、机器人自己的点击照走）、不改一次性通行证、不改被碰次数记账。
- 不动 `executor/exec-core.js`（红线）。
- 不加「干完自动关窗」的开关旋钮——老板要的就是别关，别做可选。

## 实现落点

| 文件 | 动什么 |
| --- | --- |
| `executor/exec-workwin.js` | 收尾 `closeAfter(3000)` → `holdOpen()`（登录收尾仍关）；注入锁加 `'done'` 那一态（撤锁＋顶部交接条）；`beginTask` 复用窗时收上一趟的页、清上一趟的条；报告句改口径 |
