# 客户机配置读公网 + 评论提示词重排 · 确认单

日期：2026-11-03
状态：已出确认单，等老板点头 → 出 demo → 再改代码

## 一、这次要解决的两件事

1. **配置只有一个真源：公网。** 客户机（执行器）本地只留一份缓存；每做一次操作，先把缓存刷新一遍，再动手。不允许再出现“公网人设是开馆店家、客户机读到空人设，AI 自己编成家长”的情况。
2. **评论话术提示词重排顺序、做简化。** 现在开头先写“你是一个普通用户”，人设在第 46 行才出现，规则又长又散；要改成“先定身份，再讲目标，再给材料，最后红线与格式”。

## 二、已定（老板 11-03 原话定的）

- ✅ 公网是配置的唯一真源；客户机不再自己维护一份独立配置。
- ✅ 客户机可以有配置文件/数据库形式的缓存，但**每次操作前必须先刷新缓存，再执行动作**。
- ✅ 提示词要重排顺序并简化。

## 三、我按默认定的（可改，点头前随时能改）

| # | 项 | 默认 |
|---|---|---|
| 1 | 缓存范围 | 人设、产品、知识库、获客设置、日常浏览设置、写稿规则、客服话术、发布/账号安全设置；**不含运行记录** |
| 2 | 客户机旧配置 | 保留为缓存，不清空；升级后第一次动作前会被公网配置覆盖 |
| 3 | 客户机设置页 | 收成只读状态页，只留配对与运行状态；要改配置去公网网页 |
| 4 | 下单携带的配置快照 | 取消；下单只带这一单的参数（关键词、范围、节奏等） |
| 5 | AI Key | 新接口不下发；客户机永远拿不到 Key（AI 仍走服务器出网） |
| 6 | 本机“导入整份备份” | 关掉，避免它再把本机配置整份覆盖 |
| 7 | 拉取失败 | 先重试约 10 秒；仍失败就用缓存继续，并在状态里标明“用的是上次的配置”；缓存也没有才停手 |
| 8 | 多页面同时要配置 | 一次拉取、全局共用，不各拉一份 |
| 9 | 配置变更何时生效 | 每个动作开始前必拉；长任务中途由心跳版本号发现变化后重拉 |
| 10 | 提示词改造范围 | 回复评论区顾客（主）、AI客服·评论回应、日常浏览顺手评论；写稿/发笔记/切片本轮不动 |
| 11 | 提示词简化目标 | 打法库 12 条从“每条一段长说明”压成“名称＋一句用法＋字数”；总长压到现在的一半左右 |
| 12 | 演示号/没挂线机器 | 维持现有“用不了”提示，不去拉配置 |

## 四、明确不做

- 🚫 不把运行记录（跑了几趟、回过谁、队列进度、发过的笔记档案）搬上公网。
- 🚫 不删客户机现有数据；本轮只改“读哪里”，不做清理。
- 🚫 不动发笔记、切片台、素材库、云端出片这条链。
- 🚫 不改 AI 出网方式（仍由服务器代出网）。

## 五、实现方案（点头后才动）

### 5.1 公网新增一个“给执行器读配置”的口

- 新接口：`POST /api/exec/config`，认挂线凭据（handId + token）。
- 返回一份配置包：`config`（剔除 ai.apiKey / fallbackApiKey）、`knowledge_base`、`drain_scan_cfg`、`auto_water_config`、`daily_browse_config`、`note_plan`、发布与账号安全设置。
- 同时返回一个版本号（内容哈希）：客户机拿它判断要不要重拉。
- 写稿/话术规则仍走原来的 `/api/exec/prompts`，不并进来。

### 5.2 客户机怎么改

- 新增“刷新配置缓存”动作：拉公网配置 → 写入本机缓存 → 记录版本号和拉取时间。
- 所有读配置的入口统一走缓存（`Storage.getConfig` / `getKnowledgeBase` / 三个队列配置），不再各自直读本机。
- 每个动作开始前调用一次刷新；同一动作内不重复拉。
- 心跳发现公网配置版本变了 → 重拉并记一条日志。
- 客户机设置页收成只读；本机“导入备份”入口关闭。
- 下单不再写配置快照；`laySnapshot` 只保留本单参数和运行态。

### 5.3 “一次操作”的边界（刷新发生在这些点）

- 点「开始」跑获客 / 日常浏览
- 点「搜索」
- 点「评论刷新」/「生成话术」
- 一次发布
- 一次通知回访 / 评论回应
- 打开执行器主界面（首屏）

### 5.4 失败处理

- 拉取失败：重试 3 次（约 10 秒）→ 仍失败用缓存继续 → 页面上标“用的是上次的配置（时间）”。
- 从没拉到过、缓存也没有：停手，提示“连不上公网配置，先检查网络/挂线”。

### 5.5 评论提示词的新骨架（顺序）

1. **你是谁**：人设原文放最前，紧跟一句硬身份——“你就是这个账号的号主本人，身份、经历、立场以这段为准”。
2. **这次要干什么**：推广目标 + 每条评论各挑一种打法。
3. **能用的真材料**：产品、知识库、口吻样本，压缩成短表。
4. **红线**：不许编人设里没写过的身份/经历（我家孩子、我学员、我开店…）；不许冒充家长/路人；合规禁词。
5. **输出格式**：JSON 字段与条数上限，放最后。

同时删除/改写：
- “你也是一个真实经历过这些事的普通用户” → 删除。
- 打法库里“以过来人身份”“用自己或身边人的经历”“亲身经历佐证” → 统一改成“只能用【账号人设】里写过的经历；没写就只讲判断”。
- “账号人设留空时退回普通接地气的真人” → 改成“人设空着也只按‘做这行的本人’说，不许换成家长/顾客/路人身份”。

## 六、验收（demo 和实现都按这几条对）

1. 公网改人设 → 客户机下一次动作前自动拿到；页面上能看到“配置已刷新（时间）”。
2. 公网断开 → 仍能用上次缓存跑，并明确标出“用的是上次的配置”。
3. 客户机本地旧配置被改乱 → 下一次动作前被公网配置覆盖，不影响生成结果。
4. 评论话术里不再出现人设没写过的“我家孩子/我学员”等第一人称经历。
5. 提示词总长明显变短，结构顺序为：身份 → 目标 → 材料 → 红线 → 格式。

## 七、风险与说明

- 执行器本来就要连公网领单、领规则、AI 也走公网，所以“配置也走公网”不新增命脉；只是多一次小请求。
- 长任务中途改配置：按心跳版本号刷新，下一段生效；正在生成的那一条不打断。
- 本轮不清理本机旧数据，回退空间保留。
