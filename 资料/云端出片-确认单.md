- 轨道：大改动，走澄清流程（清单 → 本档 → ~~demo~~ → 实现）。

## 〇、现状（改之前是什么样）

- **出片全在客户浏览器里跑**：`extension/lib/video/encoder.js` 用浏览器的编码器把画好的帧压成 H.264，`extension/lib/video/audio.js` 把逐幕配音转成 AAC，再合成一条 1080×1920、30 帧、每秒 8 兆比特的 MP4；一分钟片子约 60MB。
- **画面那一半不挑计时**：每帧时刻是算出来的（第几帧÷30），不是靠浏览器自己的节拍器——这条利于搬到服务器重放。
- **配音挑浏览器**：走微软给 Edge 的免费口子，靠 Edge 身份令牌，非 Edge 一律被拒（`extension/lib/video/tts-edge.js`）。
- **底图只在本机**：档案里只存不超过 160px 的预览小图和引用，全分辨率原图不入档、不上云（`extension/video.js` 的 `assetSrc`）。
- **成片落本机**：浏览器下载＋存本机 `film:<篇id>`，档案行标「代发」，发布队列素材另存 `pub:<篇id>:<i>`。
- **云端那台**：只有 Node（`server/dev-server.mjs`，80 端口，systemd 常驻），账本 `server/data/store.json`，文件区 `server/data/blobs/`；已有一张派单账本（配对号换令牌 → 长轮询拉活 → 回执），**但派的全是"回客户浏览器干活"那五类，没有任何一类是"服务器自己干"**；**没装过没界面的浏览器、没装过剪辑工具、没装 Python**。
- **现成经验**：本机 Python 脚本 `scripts/dev/render_style_film.py` 已经做过"偷偷开一个浏览器把出片页打开 → 逐帧出画面 → 剪辑工具合成配音"，这套是搬云的最短路径。

## 一、✅ 已定（逐条落成做法）

### 1. 归谁做（A1）

- **云端为默认**，客户点「🎬 出片」即提交云端；**本机那条编码链不删**，收进设置里一个开关（「云端出不了时改用本机出片」），默认关。

### 2. 提交什么（A1/B1/B2）

- 客户机只交**这一篇要出的东西**：出片稿文案、分幕切分、画面风格、字数/节奏参数、配音音色与语速、封面参数、底图。
- **底图在提交那一刻临时传原图**（走已有的 `POST /api/blob/put`），云端不常驻；外链底图由云端自己下载，抓不到就报错（见 C6）。
- **账号关系、线索、评论、通知一概不上云**——这是本轮唯一放开的上云类别，只放开"出片素材"这一条口子。
- 稿子与素材在云端**存 7 天**（旋钮）后随成片一起删。

### 3. 服务器怎么把片做出来（B4，实现路线本轮定死）

- **画面**：云端开"没有界面的浏览器"打开出片页，逐帧把画面交出来（不靠录屏抓屏，按时钟一帧一帧要）。
- **编码/合声**：**全部交给服务器上的剪辑工具**——不再用任何浏览器自带的编码器（客户机不挑，服务器浏览器也不挑，这条是老板选云端的初衷）。
- **配音**：云端按分幕逐幕念，量出真实秒数重排时间轴（与本机同一口径：片头留白 0.8 秒、幕间 0.5 秒、片尾 1.4 秒）。
- 云端要新装：**没界面的浏览器 + 剪辑工具**，`server/deploy-cloud.sh` 加这两步；老账本 `store.json` 与 `blobs/` 保留（重装＝升级，不重置）。

### 4. 配音走哪条（B3）——**2026-10-16 实测后改写，原方案作废**

**实测结论（当天）**：微软那条免费口子把进门令牌换了新版（老版参数 `1-…`、新版 `2-…`，且哈希算法换成一枚校验码加改过的摘要）。本机现装的社区库 7.2.8 用老令牌 → **403 拒**；升到 7.3.1 用新令牌 → **同一网络同一句一次念过（17.5KB 真音频）**。时钟与网络都对得上（本机 UTC 与服务器时间差 3 秒内），不是时钟问题、不是 IP 问题。

**连带影响（比搬云端更急）**：三条配音路现在**全都废着**——
- 客户机扩展里那份（`extension/lib/video/tts-edge.js`）用的还是老令牌 → 客户机即使换了新 Edge、有了那道编码工序，照样念不出声；
- 本机 Python 管线（`scripts/dev/tts_voice.py`）用的 7.2.8 → 同样 403；
- 云端还没装过配音通道。

**修法两条 → 老板 2026-10-16 圈了甲**：
- **✅ 甲（已采纳）云端装现成的社区库**：`deploy-cloud.sh` 里多装 Python + 那个念稿的库（跟着社区升级，微软再改口径我们只升一个包）。代价＝云端那台多一个运行环境。客户机那份浏览器代码本轮**不修**（配音整条腿搬到云端，浏览器里那份从此不碰——顺带把"必须用 Edge"这条限制彻底解掉）。
- ~~乙 自己把新令牌算法抄进我们代码~~（不采纳：微软每次改口径都要手工重写那 200 来行位运算，风险＝下次客户突然集体念不出声）。

**已产出（本机跑通）**：`server/film/tts.mjs`（Node 这一头，只管把稿子交给 Python、收每幕的 mp3 与真实秒数）＋ `server/film/tts-voice.py`（那一头：调社区库逐幕念、ffprobe 量秒数、版本太老直接报出来并给升级命令）。装库门槛写死在脚本里：**edge-tts ≥ 7.3.1**（7.2.8 用老令牌，实测 403）。


### 5. 排队（A2/A3/A4）

- **先来后到，一次跑 1 条**（并发数＝旋钮，默认 1）。
- **档位**：239/399/539 三档都有（字效编辑器本来就随发笔记给），**每人每天 10 条**（旋钮）；超了当天不再收，明确提示"今天云端额度用完，明天再来 / 或临时用本机出片"。
- **单条上限**：最长 3 分钟、最多 60 幕，超了提交时就拒并说明原因。
- 账本落在 `store.json`（新增一类"出片任务"，状态：待排 / 出片中 / 好片待取 / 已取回 / 失败 / 已取消）；**服务重启不能重跑已出过的片**，仿现有防重跑盖章。

### 6. 客户看到什么（A5/A6/A9）

- 提交即回**位次**（前面还排 N 条）＋**工序进度**（对稿 / 配音 / 画画面 x% / 合成 / 传回来）。
- 排队期间**客户机可以关掉走人**；下次打开扩展看到通知＋档案行「云端待取」。
- 失败：自动重跑 1 次；再失败把原因写在档案行上（配音取不到 / 底图拿不到 / 云端忙不过来 / 磁盘满），不让客户猜。

### 7. 片子怎么回来、发布谁点（A7/A8）

- 云端成片留在文件区，客户机点「取回」下载进本机（现有 `film:<篇id>` 落点不变）→ 档案行标「代发」→ **发布仍由客户机点**（碰平台的动作不出客户浏览器，这条合规口径不动）。
- 成片在云端**留 7 天**（旋钮）自动删；磁盘告急时**只删"客户已取回过"的**，没取回的不删。

### 8. 改动范围（B5/B6/B7/B9）

- **本轮改**：字效编辑器（字体动效出片）＋档案行的状态识别＋设置里的出片开关＋云端出片 worker 与排队账本＋`deploy-cloud.sh`。
- **本轮也改**：公网演示版（`web/`）那份出片代码一起走云端——否则公网那台演示时还是出不了片，讲单演示不了。
- **本轮不动**：案例流那条「🎬 拼片配音」（片段拼片＋烧字幕）仍在浏览器里录，下一条链单独一轮。
- **本轮只改一处物料**：`资料/功能与界面总表.md` 里"本机直接出片"这类口径改口；**传单/落地页/海报话术先不动**，等这条真机跑通再定印面。
- **待办挂账**：手机端执行器副本（`executor/lib/video/`）本轮不动，跟案例流一起排下轮。

### 9. 边界例外（C1–C7）

- 云端联系不上：提示"云端暂时联系不上，稍后再试"；若设置里开了本机兜底，同一条提示带"也可改用本机出片"。
- 同一篇连点两次：只允许一个在排任务（按篇盖章）。
- 片已出、稿子又改了：旧片标"稿子已改，要重出一版？"，不自动重跑。
- 排队中可取消：还没开始跑的才允许撤；已在跑的只能等结果。
- 客户没开浏览器时跑完：下次打开扩展看到通知＋档案行「云端待取」。
- 底图是外链且云端抓不到：报错并提示改选本机图。
- 取回中断：按云端文件号重新取（先不做断点续传）。

## 📌 替你按默认定的（扫一眼，不对就圈）

- **实现路线选"剪辑工具编码"**，而不是"让服务器的浏览器自己编码"——因为 Linux 上的浏览器自带音频编码能不能用不确定，这条路会把"挑浏览器"从客户机搬到服务器上，违背你要的"不挑"。
- **并发默认 1、每人每天 10 条、单条 3 分钟/60 幕、素材与成片留 7 天**——四个数全留成旋钮，按你说的服务器配置再调。
- **容量按 2 核 4G 估**（一条 2 分钟竖屏片纯 CPU 出片约几分钟），等老板给出真实核数/内存/磁盘/带宽后回填 A3/A4。
- 档案新增的三个状态词暂定：**「云端排队中」/「云端出片中」/「云端待取」**——要换叫法直接改。
- 本机兜底开关默认**关**（避免客户机五花八门，出问题说不清）。

**本机验收（2026-10-16，独立端口 + 独立账本，不碰开发那份）**
