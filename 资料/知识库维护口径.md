## 〇、这一页要回答的两个问题（老板原话口径）

1. **录入时少犯错** —— 红框 + 字数提示让坏数据进不来库。
2. **过渡态不打断人** —— 「默认」分类是历史包袱，先软警示、引导换 8 类之一，不强拒。

一句话：录入页从「写完再报错」升级为「一边写一边标红 + 字数一接近上限就橙」。

## 四、tag 解析规则

```js
function _diagKbParseTags(raw) {
  const text = String(raw || '').trim();
  if (!text) return { ok: true, tags: [] };            // 空 = 合法（不报错）
  try {
    const v = text.startsWith('[') ? JSON.parse(text)  // 优先 JSON
                                   : text.split(/[,，、\n]/)  // 否则按 , ， 、 换行 拆
                                          .map(t => String(t).trim())
                                          .filter(Boolean);
    if (!Array.isArray(v) || v.some(t => typeof t !== 'string')) throw new Error();
    return { ok: true, tags: v };
  } catch (_) { return { ok: false, tags: [] };       // 解析失败 → 红框
}
```

- **分隔符**：`,`（半角逗号）、`，`（全角逗号）、`、`（顿号）、`\n`（换行）四种任一
- **空白**：自动 trim + filter 空
- **JSON 路径**：首字符是 `[` 就走 JSON.parse（必须是字符串数组，非字符串元素抛错）
- **空字符串**：合法、不显示警示

—— **示例值**：写「流量焦虑、付费转化、复购」→ 3 个标签；写 `["流量焦虑","付费转化","复购"]` → 3 个标签；写 `流量焦虑 付费转化`（空格分隔）→ 解析失败、红框。

## 五、分类 = 「默认」软警示的设计动机

> 这是 KB_CAT 升级（`资料/小红书AI引流系统-知识体系总览.md` §七）的**过渡态**。

- 历史数据里有大量「默认」分类的旧条目（落 `category = '默认'`）
- 升级 8 类口径后，新建条目**不允许**再选「默认」（分类必填、且只下拉 8 类之一）
- 但**老条目仍带「默认」**——打开编辑时不能让红框 / 拒存拦着用户
- 折中：值 = 「默认」时给黄边 + 提示「建议换成 8 类之一」，但不阻存；保存照旧覆盖原值
- 下一步如果「默认」条目清零（手动迁移完），警示可整体退役

## 八、🚫 明确不做（防范围膨胀）

1. **不引入富文本编辑器** —— 沿用 `<textarea>`，不接 marked / quill
2. **不实时调 AI 校验** —— 录入页只做格式校验，AI 改稿是另一段
3. **不做图片 OCR 校验** —— 配图可选，不强制
4. **不做必填之外的强校验**（如「标题不能全数字」「正文必须有图片」之类）—— **本期不做**
5. **不写「默认 → 自动迁移到某类」** —— 用户手挑，不替用户做主
