# 日常浏览 · 队列编排版（设计定稿 v3 · 2026-09-26）

> 内部设计稿。合规：界面与交付物料不出现「养号」等禁用词，功能对外一律叫「日常浏览」。
> 一句话：日常浏览是获客队列里的一种**流程项**——和「词 × 类型」格子排在同一条时间轴上；**每天自动生成一份今日队列，每天自动跑**。
>
> 变更记录：
> - v2（2026-09-26）：不再是"独立功能 + 让路"，改为**队列里的一种可编排流程项**；配置进「任务配置」三级 tab；动作与获客台账彻底隔离。
> - v3（2026-09-26）：确认**保底时钟要**，且升级为「**每天一份今日队列 + 每天自动跑整条队列**」（含获客格子）。
> - v4（2026-09-27）：总开关口径收紧——「开启」只管**自动排**；**手插的一轮是显式指令，关着也照跑**（方向停用 / 今日配额满仍拦；不在时段不拦）。此前三层不一致：队列页能塞、派生队列认它、执行器却按总开关整轮跳掉。

## 〇、使用形态（先看这段）

- **每天一份今日队列**：到点自动派生今天的队列——获客格子（按各自节奏到点）+ 按**塞入规则**排进来的日常流程项。队列页看到的就是"今天的计划"，可手动加/拎到最前/删。
  - 不落快照、仍现场派生（**改表即时生效**，不存在两份要同步的计划）；"今天跑过什么"由现有的 `done / carry / lastAt` 机制记账。
- **每天自动跑**：不用点「🤖 开始」。到点自动把插件大窗拉起来（不抢焦点）→ 自动开跑 → **守到今天没活为止**（到点项跑完、剩下的没到点就等），然后收工。
- **一条时间轴、串行**：同一时刻只有一件事在动页面这件事天然成立（都在同一个执行器里排队）。
- **可开可关**：日常浏览关掉 → 队列不再**自动**排它，只剩获客格子；**手插的一轮（队列页「塞一轮」）照跑**——那是人当下点的显式指令。
- **不进获客的账**：日常流程的动作（打开/赞/藏/评论/回复/关注）一律不写获客台账，消息中心、通知、线索、评论记录里都看不到它（见第五节）。

## 二、数据结构

### 配置（`daily_browse_config`）
```
{
  enabled,                       // 日常浏览总开关（可开可关）
  insert: { everyN: 3 },         // 塞入规则：每 N 个获客格子插 1 轮；0 = 只手动塞
  directions: [
    { id, name: '读书', enabled: true,
      keywords: ['...'],         // 空 = 该方向走首页推荐
      windows: [{start:'09:00', end:'11:30'}],
      dailyQuota: 25,            // 该方向每日浏览上限
      weight: 60                 // 轮转权重（多方向之间谁更常被挑中）
    }, ...
  ],
  // ── 全局（号级行为尺度，所有方向共用）──
  perRound: 6, intervalMin: 25, dwellMin: 8, dwellMax: 25,
  openRate: 60, likeRate: 25, collectRate: 12,
  comment: { rate: 10, dailyMax: 5 },   // 打开的笔记里 10%、每天最多 5 条
  reply:   { dailyMax: 2 },             // 每天最多 2 条（AI 挑条）
  follow:  { rate: 8, dailyMax: 3 },    // 打开的笔记里 8%、每天最多 3 个
  pool: ['...']                          // 本地句池（可编辑，AI 兜底）
}
```

### 计数（`daily_browse_daily`）
`{ date, byDirection: {dirId: n}, comments, replies, follows, rounds }`（旧字段做一次迁移）

### 队列项（复用现有 `(来源, 类型)` 元组）
- 现有：`(词, 最新/TOP/高V/本地)`、`(主页链接, 关注)`
- 新增：**`(方向id, daily)`** → `{ k: dirId, scenario: 'daily', label: '🌿 日常流程 · 读书', source: 'auto'|'manual' }`
- 来源角标：`auto`＝系统按塞入规则排的；`manual`＝你手插的。都走现有的 `manual`/`carry`/`todo` 机制。

## 三、队列编排

1. **自动塞**：派生队列时，把日常流程项插进排序链的第 N / 2N / 3N … 位。
   - 方向怎么挑：候选 = 启用 + 在自己的时段内 + 该方向今日未满配额；加权随机挑一个。
   - 不在任何方向时段内 → 不插（顺延到下一个落进时段的插入位）；各方向配额都满 → 不插。
2. **手动塞**：队列页「+ 塞一轮日常流程」→ 选方向（或"用当前时段该跑的方向"）；插进来排最前（复用现有手插语义），也能删。
3. **跑**：执行器轮到 `scenario='daily'` 的项 → 调"跑一轮浏览"（篇数 = min(perRound, 该方向今日剩余配额)）→ 记账、写日志（行首带方向名）→ 继续下一项。
4. **失败/中断**：跟获客格子同一套——撞上限或被停记欠账，下次接着跑。

## 四、动作与通路

| 动作 | 通路 | 复用 / 新增 |
|---|---|---|
| 浏览 / 打开阅读 | `browseRound` 现有 | 复用 |
| 点赞 / 收藏 | `_dbEngage` 现有 | 复用 |
| 顺手评论（对笔记） | `sendNoteComment`（一级评论，含定位/提交/验证/防重） | **函数直调**复用；文本 = AI 独立提示词 + 本地句池兜底 |
| 回复别人的评论 | 获客回复的「定位评论 → 回复 → 发送 → 验证防错位」通路 | 复用发送；**选条用 AI 判定**（新增一小段：取评论 → AI 选 → 回） |
| 关注作者 | `followUser`（按用户名找关注）+ 笔记页作者区关注 | 部分新增；已关注则跳过 |

## 五、隔离：不碰获客的账（v2 硬约束）

日常流程产生的一切动作**只写自己的两本账**（`daily_browse_log` / `daily_browse_daily`），**一律不写**：

- `watering_logs`（笔记池页尾「💬 评论记录」）
- `watered_notes` / `replied_comments` / `opened_notes`（已灌水 / 已回复 / 已打开）
- `prospect_list` / `prospect_dm_history`（获客清单 / 私信历史）
- `chat_follow_state` / `chat_follow_reply_history`（通知页会话与回复历史）
- `auto_water_*`（队列进度 / 历史 / 每日计数）
- 消息中心 / 通知页的任何数据源

且**不在工作台、笔记池上打任何标记**（不会出现"已灌水 / 队列跑过 / 已回复"）——养号的痕迹只在「任务配置 → 日常浏览」的状态区看得到。

## 六、每天自动跑（v3，保底升级版）

1. **每日闹钟**（后台）：到点（每天首次唤醒 / 0 点后）派生今天的队列并检查"今天还有活"。
2. **拉起执行器**：若插件大窗没开 → `chrome.windows.create('popup.html?mode=big', { focused:false })`（复用现有 `bigWindowId` 机制，不抢焦点）→ 等页面就绪 → 切到「获客 · 工作台」视图 → 自动启动队列。
3. **守着跑**：执行器不再"没到点的就收工退出"，改为**到今天没活为止**（到点项跑完 → 等下一个到点项；当天全部跑完 → 收工）。
4. **跑完**：若窗口是自动开的且你没在用它 → 自动关掉；你手动开的窗口不动。
5. **看门狗**（撒手加固）：每 ~20 分钟确认"今天还有活 + 执行器没在跑" → 重新拉起；连续失败 → 状态区红字提示。
6. 手动「🤖 开始」按钮保留：临时插队跑（已经在跑就忽略）。

## 七、技术前提与风险

1. **锁与心跳**：页面侧只有一个全局操作锁，"持锁超 30 秒会被下一个操作强夺"。一轮浏览持锁 1~3 分钟，靠 `_touchLock` 心跳压着——多数间隔 <10s，但"点了笔记没打开"那段有 **~25s 空档**。→ **把心跳补密**（几行）。
2. **必须函数直调**：评论/回复/关注不能走 `chrome.runtime.sendMessage` 消息路由（路由会二次抢同一把锁 → 必然失败），要把这几段抽成可直接调用的内部函数。
3. **防重口径沿用**：同一笔记同内容不重发（`_sessionNoteCommentSigs`）；关注前先查"已关注"；回复沿用会话级防重与交叉验证。
4. **执行器扩展（主要改动量）**：
   - 队列项多一种 `scenario='daily'`，执行器要能识别并调"跑一轮浏览"，而不是走"搜索 → 灌水"；
   - 执行器要能被后台**自动拉起**（现在必须有人点「🤖 开始」），且要能在"没到点"时驻留等待而不是退出；
   - 它住在弹窗页里、靠点页面里的按钮干活（`#noteList .note-item` / `.btn-open-note`），所以自动跑必须先把窗口开起来并切到工作台视图。
5. **抢前台**：页面动作需要把小红书页切到前台（现状 `_activate` 会激活标签页 + 聚焦窗口）。自动跑时会在你工作途中切屏——先按现状接受；若嫌吵，后续可加"检测到用户在操作就延后"。

## 八、界面

- **任务配置 → 三级 tab「🌿 日常浏览」**：开关（标题行尾「⏹ 停止本轮」）/ 状态区 / 方向列表（列表先查看摘要，编辑进弹窗，可停用不必删）/ **什么时候跑**（每 N 格插一轮 + 每天自动跑时段）/ **一轮怎么刷**（折叠块：每轮篇数、停留、打开/点赞/收藏概率）/ **顺手互动**（折叠块：评论概率与日上限、回复日上限、关注概率与日上限）/ 本地句池一个可编辑文本框。状态区示例：`今日 42 篇（读书 25 · 体育 17）｜评论 3 · 回复 1 · 关注 2 ｜ 当前方向：读书 ｜ 下一轮 14:35`。
  - 版面口径（2026-09-27 改）：成句说明收成**行尾问号**（鼠标停上去出气泡，实现＝`.sx-help` 的 `data-tip` + `::after`，不用原生 title：1 秒延迟且不换行），页面只留防误操作的短句（起止填一样＝全天 / 按篇的概率，不是每篇都做 / 上限填 0＝不做 / 一行一条）；两组旋钮折成一行摘要 + 「改」，摘要随改动刷新、展开态跨重渲染保留（`_dbDetOpen`）。回归：`python3 scripts/dev/check_daily_cfg_ui.py`。
- **队列页**：日常流程项跟获客格子同一列卡片（角标 🌿 + 方向名 + 「系统塞的 / 手插」）；顶部「+ 塞一轮日常流程」；今天有一份完整的"今日队列"（含到点时间）。
- 日志每行带方向名（`[14:12] 本轮完成：读书 · 搜索「××」· 浏览 6 篇…`）。

## 十、默认数值（可调，先按这套写）

- 塞入规则：每 **3** 个获客格子插 1 轮日常流程
- 顺手评论：打开的笔记 10%、每天最多 5 条
- 回复：每天最多 2 条
- 关注：打开的笔记 8%、每天最多 3 个
- 方向：上限 8 个，权重默认均分
