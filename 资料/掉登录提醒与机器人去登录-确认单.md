# 掉登录提醒 ＋「让机器人那台电脑去登录」— 确认单（已落地版）

- 日期：2026-11-04（11-04 已按本单落生产代码，本机自测全过，**尚未推公网**）
- 起因：小红书在浏览器里退登后，只有右上角胶囊一颗小黄灯；客户在获客工作台、发笔记工作台里看不出来，活到点也跑不了。
- 结论：**右上角「❓ 新手引导」左边亮一颗实心红标「📕 掉登录 · 去登录」**（带呼吸光圈，最显眼的那颗）；点它由**执行器那台电脑**打开小红书登录页等扫码，登好后红标自己收。胶囊、账号菜单、发笔记工作台、「今天」小窗同步跟着变。

---

## 一、这轮用到的词

- **掉登录**：绑定的号在浏览器里退出了，机器人打开页面看不到「已登录」。
- **号不对**：浏览器里登的是另一个号，跟绑定的对不上。
- **认号**：执行器每次开窗干活时顺手看一眼登的是哪个号，报回服务器（`bindState`）。
- **胶囊**：右上角「头像＋名字＋档位＋三盏灯」那一颗。
- **红标**：本轮新加的那颗红色按钮，固定在胶囊和「❓ 新手引导」中间。

## 二、已定口径（老板 2026-11-04 确认）

### ① 提醒放哪

**主提醒＝右上角红标**（老板原话：「不是在这里显示的，是在右上角新手引导那个执行器状态那里显示，还要再调显眼一点」）。
- 顶栏下面那条通栏横幅**不做**——原先方案是横幅，已按老板改口撤掉。
- 红标：实心红底白字＋呼吸光圈，文案「📕 掉登录 · 去登录」；窄窗（640 弹窗）只留「📕 掉登录」。
- 胶囊同时变红边红底，点开菜单最上面一行为红行＋「🔐 去登录（那台电脑）」。
- 发笔记工作台「这轮挂哪几家」上面加一行红字（老板点名的页面）。
- 「今天」小窗标题变成「小红书掉登录了」，按钮就是「去登录」。

### ② 管哪些页面

全站右上红标常驻（顶栏每页都有）；发笔记工作台那一行只在发笔记工作台。「今天」小窗共用同一套判断。

### ③ 点「去登录」谁去登

**执行器那台电脑（BOT 机器）去登录，不是当前这个网页所在的浏览器。**
- 网页发一条「登录机器人」的令 → 执行器在那台机器上打开小红书登录页、把窗口端到最前、等人扫码。
- 扫完码执行器自动认号、报回服务器；网页这边**不用刷新**，几秒内红标自己消失。
- 客户在手机上开网页点「去登录」，也是那台机器人电脑弹登录页。

### ④ 报哪几种坏状态

**「掉登录」和「号不对」都报，文案分开。**
- 掉登录 → 在装执行器的那台电脑上登回原来的号。
- 号不对 → 这台电脑登的是「另一个号」，换回原来的号再点一次。
- 小红书一定报；抖音在「全平台版」里算必报；视频号只有绑过才报（可选平台，没绑不欠账）。

### ⑤ 坏了怎么关掉

**不给永久关，也不给「收起」。** 红标一直在，直到登回来认号成功才消失。
- 理由：客户一关就忘，到点活没跑才回来找，更麻烦。

### ⑥ 多个平台一起坏

红标先显示最要紧的那家（**小红书排最前**），悬停／菜单里把坏的全列出来；点一次处理一家，处理好下一家红标接着亮。

### ⑦ 登回来怎么消

下一次认号报回「已登录」就当场消失（网页每 5 秒本来就在拉一次执行器状态，不新增接口）。点了「去登录」但还没扫完时，红标变「⏳ 等你扫码…」并置灰，防止连点。

## 三、⚠️ 系统碰撞与解法（逐条）

### 1. 给执行器加了一个新动作

- 内部名：`relogin`（显示名「登录机器人」），参数 `platform`（默认 xhs）。
- 执行器接到后走现有「认一下」那条路：打开登录页 → 等扫码 → 扫上自动认号 → 报回服务器。
- 不干活时能单独跑；正在跑别的活时**不插队**（免得登录页顶掉干活窗口）。
- **不卡档位、不卡暂停**：老板按了小红书暂停照样能点去登录（暂停挡的是获客/日常浏览，不该挡住修号）。

**代价：执行器包升版 1.8.0 → 1.8.1。** 按现有版本闸规矩，已装 1.8.0 的客户机不换新包会被停派，必须重下专属包——这条和以前每次执行器发版一样。

### 2. 只有小红书会「等人扫码」

`bindNow` 里只有小红书配了 10 分钟等待；**抖音开页面就关、视频号只能靠面板点「认一下」**。所以：
- 派给小红书的令：扫码页留着，最多等 10 分钟，扫上自动认号 → 网页红标自动收。
- 派给抖音/视频号的令：那台电脑打开登录页，**扫完之后要在执行器面板点一下「认一下抖音/视频号」**，网页这边才知道登好了。
- 这点在执行器的回执文案里已经写明白，不会让人以为扫完就完事。

### 3. 状态不是实时的

`bindState` 是执行器**上一次开窗认号时**看到的结果。客户刚在浏览器里手动退出、机器人还没跑，网页不会立刻知道。本轮不加后台常驻探测，沿用 5 秒轮询＋打开页面即刷新。

### 4. 别两处一起喊

`exec-bridge` 原来那条「撞号/掉登录」的浮层红条，在右上角红标亮着时**不再重复出现**（红标位置更固定、更显眼）；只有页面没有红标位时才回退用旧浮层。

### 5. 窄窗（640 弹窗）放不下

窄窗时：红标只留「📕 掉登录」，胶囊里的「已绑 2/3」小标收起，顶栏的品牌名和运行状态徽章让位（红标亮时才收，恢复正常就回来）。

### 6. 哪几份代码要跟

- 公网 `web/`：本次主改（那份是去注释版，推的时候按块贴，**不整份盖**）。
- 执行器主本 `executor/` ＋ 客户包母版 `web/download/_proto/`：一起升 1.8.1，已用 `node executor/pack.js` 重铺并逐字节核对一致。
- `extension/` 自测副本：**本轮不跟**（它没有账号体系，这段本来就不跑）。

### 7. 演示号 / 没装执行器 / 还没绑号

都不报「掉登录」：
- 演示号没有执行器，`bindState` 为空 → 一律「用不了」，不亮红标。
- 没装执行器 / 没绑号走「去装 / 怎么绑」的引导，不是「掉登录」。

## 四、点「去登录」的完整流程

```
网页（任何一页）
  └─ 右上红标 / 胶囊菜单里点「🔐 去登录」
       ├─ 执行器不在线 → 当场提示：那台电脑的执行器现在没连上，点开执行器图标连上再点
       ├─ 正在跑别的活 → 提示：那台电脑正在干活——等这一趟跑完再点
       ├─ 老包（1.8.0）→ 提示：版本太旧不会这个动作，重装最新执行器
       └─ 可派 → 下单 relogin（platform = 第一个坏的平台）
             └─ 执行器那台电脑：
                  打开小红书登录页 → 窗口端到最前 → 等扫码（最多10分钟）
                  扫码成功 → 自动认号 → 报回服务器（bindState = ok）
                  10分钟没扫 → 报回「没扫码」；红标继续在，提示再点一次
网页：不刷新，红标先变「⏳ 等你扫码…」；下一次 5 秒轮询看到 ok → 红标自己消失
```
