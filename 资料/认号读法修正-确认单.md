# 认号读法修正 · 确认单（2026-10-25）

> 背景：小红书登的是「杨小过」，认号读出来却是「JQK（11670972460）」；抖音读出「bok（72007330844）」，待你确认对不对。
> 你选的方案：认不准就报没认上、你手动打开本人主页再点一次（A）；后台只做「清掉重认」，不做手填（1）。

## 一、出了什么事

- 挂执行器的那个浏览器里，小红书登的是**杨小过**。
- 后台记下的却是**JQK / 11670972460**——不是你的号。
- 抖音那格记的是**bok / 72007330844**。抖音这条是直接打开「本人的抖音页」读的，不会猜——所以它读出来是谁，说明那个浏览器里抖音登的就是谁。**bok 是不是你的号，需要你确认一句。**
- 后果：队列要跑小红书＋抖音，后台以为两个号都认过了（认的是错的）。轻则拿错号去搜，重则开工时两边都报「对不上」。

## 二、病根

认号要先「找到本人主页」，现在的找法有两步：

1. 先看小红书站内登录缓存里记的本人 id；
2. 读不到时，**退而拿页面上第一个头像链接去猜**——推荐流里作者头像也长这样，于是跳进了别人（JQK）的主页。

而别人的主页上也写着「小红书号」，程序就把它当成本人了，直接绑上。

一句话：**它没有「确认这是本人」的能力，只有猜。**

## 三、改法

### 1. 认号只认本人（执行器）

按顺序取本人 id，全部来自「登录态」，不再从头像链接猜：

1. 站内左侧「我」入口的链接（当前登录的本人，最可靠）；
2. 站内登录缓存（只在 id 格式对得上时用）；
3. 前两个都拿不到 → 自动点一次「我」入口，等页面跳到自己主页再读。

三个都拿不到 → **不绑、不猜**，提示：

> 没认上：先在干活窗口打开你自己小红书的「我的」主页，再点一次「认一下」。

你手动打开本人主页后点「认一下」，就按当前这页认（你要的 A 方案）。

### 2. 后台能看、能清（修正认号）

位置：后台账号表 → 每个号都有「小红书」「抖音」两格。

- 每格显示：**绑的号（昵称）＋ 最近一次这台机器实际读到的是谁 ＋ 时间**；
- 按钮「换绑」改成「**认号不对？清掉重认**」，点之前弹窗说清三件事：
  - 只清这一格，另一个平台一点不动；
  - 这台机器会被踢下线，要重新挂一次线；
  - 重新挂线时会自动再认一次。
- **不做老板手填号**（按你选的 1）。

## 四、要动的文件

| 文件 | 改什么 |
| --- | --- |
| `executor/content.js` | 找本人主页：改走「我」入口／登录缓存／点「我」，删掉拿头像链接猜的旧路 |
| `executor/exec-acct-check.js` | 认号流程：读不到就报「没认上」；你手动打开的本人主页也能认 |
| `executor/manifest.json` | 版本 1.4.0 → 1.4.1 |
| `web/admin.html` | 认号那格：加「最近读到谁＋时间」、按钮改成「清掉重认」并说清后果 |
| `web/download/` | 重新打包执行器（自动留旧包可回滚）→ 推 zip ＋ 版本号文件 |

## 五、上线与验收

推包之后：

1. 你在扩展页点一次「重新加载」（同目录，配对号不丢）；
2. 后台把小红书、抖音那两格清掉 → 重新挂一次线，让它自己认一遍。

验收四条：

1. 后台小红书那格显示的是**杨小过**那个号的号＋昵称；
2. 抖音那格是你要的抖音号；
3. 故意在没登录的窗口点「认一下」→ 报「没认上」，**不会绑到陌生人**；
4. 队列点开始 → 两边都按绑定号跑。

不需要重启服务器（这次只动执行器包和静态后台页）。

## 六、风险

- 还在用 1.4.0 的机器不换 1.4.1，会被版本闸拒（这是现有规则，不是新加的限制）。
- 清格会把这台机器踢下线，需要重新挂一次线。

## 七、要你点头的三处

1. 认号读不到时报「没认上」＋你手动打开本人主页这条路（A）——已选，请确认。
2. 后台只做「清掉重认」，不做手填（1）——已选，请确认。
3. **那个浏览器里抖音登的是不是 bok？**如果是，这次两块一起改；如果不是，说明浏览器登的号不对，要先在浏览器里换成你的号，再走清格重认。
