# 获客清单功能设计文档（v2 · 二级管线版）

> 小红书评论助手插件新增功能：扫描笔记评论 + 通知页互动 → 人群两级分层（线索/商机）→ AI 画像 → 个性化私信 → 人工确认发送 → 分阶段推进 → 定向销售

**本版相对 v1 的定位调整（为什么重设计）：**
v1 把"线索 / 商机 / 客户"三种本质不同的人混进同一张平铺表，用 `dmStatus`（私信漏斗）+ `customerStatus`(客户生命周期) + `intentLevel`（意向）三套互不隶属的状态并存，导致 UI 同时显示彼此雷同的徽章和下拉、AI 场景膨胀到 7 个且反复判断"该不该跟进"。v2 的核心改法：

1. **人分层，而不是混一池** —— 一条 `stage`（lead / prospect）驱动一切，每层有独立收录标准与动作。
2. **去掉客户层** —— 对小红书卖货来说本质只有"**接触过没**"和"**买不买**"，而成交基本不走私信控制，单独建客户层意义不大。所以 **lead = 未接触，prospect = 已接触**；成交只在商机上做个标注（`funnel.step='closed'`），不再单独分层。
3. **一套状态** —— 子状态绑定在所属层内，删除三套并存。
4. **收敛 AI 场景** —— 保留 3 个（画像 / 私信 / 入池路由），规则型逻辑下沉为本地代码，不再烧 AI。

---

## 一、功能定位

### 1.1 一句话定位
**可推进的销售管线（Pipeline）**：不是"收藏了多少人"，而是"每个人在哪一层、下一步该做什么、做完全往哪走"。把小红书捞到的人按阶段经营，直到成交。

### 1.2 入口位置

popup 弹窗左上角 tab 区新增第三个按钮，与现有两个 tab 并排：

```
📄 评论助手 | 💬 评论跟进 | 🎯 获客清单
```

- 文件：`extension/popup.html`，在 `#mainTabs` 区域新增：
  ```html
  <button id="tabProspectList" class="main-tab" title="获客清单：人群分层+定向私信">🎯 获客清单</button>
  ```
- Tab 切换逻辑：复用 `popup.js` 中 `switchMainTab()`，新增 `'prospectList'` 分支（隐藏其它内容、显示 `prospectContent` 容器、隐藏左栏笔记列表、工具栏切到 `'prospectList'` 模式）。

### 1.3 私信自动化程度

**AI 生成 + 人工确认发送**。系统只负责给每层人"建议动作"，最终发送仍由人点一下才真的发。

## 二、核心概念：二级管线（Pipeline）

```
  线索池 Leads ──接触(做了动作)──▶  商机池 Prospects
  (未接触)                          (已接触，重点经营；成交在此标注)
```

| 层 | 定义 | 主要来源 | 系统建议动作 | 出口 |
|---|---|---|---|---|
| **线索池 Leads** | 未接触：被动信号的泛流量，AI 不筛，零门槛 | 赞/收藏/关注了你的人、关键词命中、普通评论 | 不主动硬推；发私信/手动升格即视为"接触" | 接触 → 自动进商机池 |
| **商机池 Prospects** | 已接触：做过动作的人，重点经营 | 评论搜索「入清单」、AI 路由、评论跟进、回复你的评论 | 画像 → 个性化私信 → 谈单 → 成交 | 成交标注（`funnel.closed`），不单独分层 |

**关键改法**：
- **接触即商机**：对线索池里任何人发了私信 / 主动升格，`lead → prospect` 一次到位，不再等待"二次被动信号"。
- **无客户层**：成交不走私信控制，只把 `funnel.step` 标成 `closed` 作记录；售后/复购/沉睡等旧概念不再单独维护。
- **并入通知页互动**：赞你评论、回你评论、关注你的人都会进清单（回你评论的直接进商机池，赞/关注你的进线索池）。

**关键改变**：点赞户等泛流量**不再默认 pending 就能发销售话术**。它先在池外养着，命中二次信号才升格，既省私信额度，也避免一上来就招黑/触发风控。

## 三、数据模型

### 3.1 候选人 `prospect_list`（按租户隔离）

每条候选人（Person）结构：

```js
{
  id: "p_1699...",                      // 唯一 id
  userId: "5c9d...",                    // 稳定 id，判重主键
  nickname: "努力攒钱的小张",
  stage: "prospect",                    // ★ 唯一真状态：lead / prospect / customer
  source: {                             // 来源快照
    stageEntry: "关键词命中",            // 从哪个入口进（见 3.3 stageEntry 口径）
    noteTitle: "首套房贷款...",
    noteUrl: "...",
    comment: "评论原文",
    userUrl: "..."
  },
  profile: {                            // AI 画像（可手动改；未画像为 null）
    tags: ["首套刚需", "预算敏感"],
    identity: "95后打工人",
    needs: "想了解首套房贷利率",
    painPoints: "怕被中介坑",
    dmAngle: "私信切入角度"
  },
  lead: {                               // ★ 仅 lead 层有意义
    signalCount: 1,                     // 互动信号次数（点赞/评论/二次触达）
    signals: ["comment:首套利率多少"],  // 信号事件列表（最近 N 条）
    lastSignalAt: 1699...
  },
  funnel: {                             // ★ 仅 prospect 层有意义（替代原先 dmStatus）
    step: "touched",                    // pending(待触达) / touched(已触达) / replied(已回复) / talking(谈单) / closed(成交)
    dmCount: 0,
    lastDmAt: null
  },
  account: {                            // ★ 仅 customer 层有意义（替代原先 customerStatus/dormant）
    status: "maintain",                 // maintain(正常维护) / after_sale(售后) / dormant(沉睡) / repurchase(复购意向)
    value: null,                        // 成交金额/客单价（可选）
    closedAt: null
  },
  affinity: {                           // 全局排序权重，仅作排序，不参与分类
    intentLevel: "high",                // high / medium / low
  },
  createdAt: 1699..., updatedAt: 1699...
}
```

### 3.2 私信历史 `prospect_dm_history`（按租户隔离）

```js
{
  id: "dm_...",
  personId: "p_...",
  nickname: "...",
  text: "发送的私信内容",
  aiGenerated: true,
  status: "sent",                      // sent / replied
  repliedText: "",
  sentAt: 1699...
}
```

### 3.3 收录入口口径 `stageEntry`

统一每个入口进到哪一层，替代 v1 的 `origin`（origin 无数值语义、靠优先级 hack）与 `keywordHit='__liker__'` 这类魔法值：

| stageEntry | 收进哪层 | 说明 |
|---|---|---|
| `点赞` | lead | 只有互动信号，未证明需求 |
| `评论` | lead | 只有评论，未判需求 |
| `关键词命中` | lead | 命中关键词但 AI 未判商机 |
| `AI路由` | prospect | AI 判为真实需求，直接入商机池 |
| `评论跟进` | prospect | 对话中确认过需求的人 |
| `手动` | (用户自选) | 手动添加时由用户指定层 |

### 3.4 状态推进规则（核心，替代 v1 的三套并存）

> 所有推进都由**明确的动作**触发，同一层内只是"下一步该做啥"的变化；跨层才是真正的升格/降格。

- `lead → prospect`（升格）：命中二次互动信号 或 用户手动升格。动作：先画像再允许私信。
- `prospect → customer`（升格）：`funnel.step` 置 `closed`（成交）。记录 `account.value / closedAt`。
- `customer` 内部：`maintain / after_sale / repurchase` 由人工维护；`dormant` 由**本地规则**自动判定（见 5.2）。
- `prospect → lead`（降格）：连续无回复、判为无效，由用户手动降级（不自动降，避免 AI 误判）。

## 四、AI 场景（收敛到 3 个）

v1 有 7 个（`prospect_finder / prospect_screener / prospect_profiler / prospect_capture / prospect_dm / customer_status / sale_timing`）。v2 收敛到 3 个，砍掉的场景职责如下：

| v1 场景 | 处置 | 归属 v2 |
|---|---|---|
| `prospect_finder` | 保留并行变成路由判断的一部分（见下） | `prospect_router` |
| `prospect_screener` | 删除（省 AI 钱的轻量判断并入路由的 `fast` 模式） | `prospect_router` |
| `prospect_profiler` | **保留** | `prospect_profiler` |
| `prospect_capture` | 改名增强为路由 | `prospect_router` |
| `prospect_dm` | **保留** | `prospect_dm` |
| `customer_status`（沉睡预判部分） | 下沉为本地规则，不调 AI | 无 prompt |
| `sale_timing` | 删除（"时候到了没"由推进规则/人工决定，不烧 AI） | 无 prompt |

### 4.1 `prospect_router`（替代 finder/screener/capture）

**职责**：只看一件事——"这条评论值不值得进商机池"，并给一句理由。**不做画像、不做话术、不判时机。**

- **System Prompt**：输出严格 JSON 数组 `[{ idx, take: true|false, why }]`；`take=true` 判定标准 = 对方表达出真实需求/求助/纠结（如"月供太高怎么办"），点赞/客套/纯闲聊一律 `take=false`（待在 lead）。
- **`selectFast`（省 AI 钱）**：先跑本地自检（纯规则），只有值得的才送 `prospect_router` 完整判断，同 v1 商机快筛的思路，但只产 `take` 判定。

### 4.2 `prospect_profiler`（画像，保留自 v1）

输入 `userId/nickname/评论/来源笔记`（多条）→ 输出结构化 JSON（`tags/identity/needs/painPoints/intentLevel/dmAngle`）。仅对 **lead→prospect 升格后** 及手动添加的商机执行。

### 4.3 `prospect_dm`（私信，保留自 v1）

强约束不变：第一句引用对方评论原话；先给价值再轻带产品；第一封绝不放链接/微信号；口吻像熟人；≤150 字；无客服腔。输入画像+评论+知识库 → 输出 `{ dm_text }`。

## 五、规则型逻辑（本地代码，不烧 AI）

### 5.1 关键词收录 → 一律进 lead 池
本地比对 `config.product.targetKeywords`，命中但 AI 未判商机的人进 lead，`stageEntry='关键词命中'`（v1 会直接 pending 成"待私信"，v2 明确它只是线索）。

### 5.2 沉睡自动判定（原 `customer_status` 的规则部分）
- prospect 层：发过但 `config.customer.dormantDays` 天无回复 → 自动标 `funnel.step='replied'` 不动，仅提示可降格。
- customer 层：`account.status` 置 `maintain/after_sale` 超过 `dormantDays` 天无互动 → 自动标 `dormant`。
- 纯本地规则，无 AI 调用。

### 5.3 二次信号 → 升格
lead 或 customer 池内的人再次点赞/评论/打开主页 → `lead.signalCount++`、记录 `signals`；`prospect` 层无此逻辑。连续 `dormantKeepDays` 天无信号 → 提示移除。

## 六、UI 交互（适配 popup 宽度）

### 6.1 主视图：三层分页 Tab，而非一张平铺表

```
全部      🎯 商机池       🤍 线索池       💰 客户池
[漏斗卡]  [重点经营对象]  [泛流量待养]    [成交/售后]
```

- 顶层切层；每层内再按 `step/status` 筛。（v1 用 `all/liker` 两档 + 各种来源 chip，v2 直接用三层分页，来源只在卡片上标 stageEntry 徽章。）

### 6.2 统计条（4 张卡片）
- 商机池 · 待触达（`funnel.step=pending`）
- 商机池 · 已回复聊单中（`replied/talking`）
- 客户池 · 全部
- 客户池 · 沉睡需唤醒

### 6.3 筛选行
- 层内二级筛选：商机池按 `funnel.step`；客户池按 `account.status`；全量可加昵称搜索。（意向高中低只作排序，不进筛选。）

### 6.4 人员卡片
按层显示不同字段，避免 v1 一张卡堆三类信息：

| 区块 | 描线 |
|---|---|
| 顶部 | 昵称 + stageEntry 来源徽章 + 层内状态徽章 + 意向色点 |
| 线索池卡 | **下一步建议**＋「升格→商机」「移除」，不出现私信按钮 |
| 商机池卡 | 画像摘要 + 评论原文 + 动作「✉️ 私信 / ⚡ 画像 / ✔️ 成交 / 🗑️ 移除」 |
| 客户池卡 | 成交信息 + 售后/复购动作 +「唤醒沉睡」 |

### 6.5 私信闭环（沿用 v1，只作用于商机池）
清单页「✉️ 私信」→ 弹窗 →「🤖 AI 生成话术」→ 人工改 →「发送」→ `sendDm` 驱动 content.js 打开主页→点私信→逐字输入→发送 → 写历史、`funnel.step` 从 `pending→touched`。回复后人工标 `replied→talking→closed`。

### 6.6 批量动作
每个动作在卡片列表里**整层执行**，且和各层的出ロ绑定：线索池「批量升格至商机」；商机池「⚡ 批量画像」「✉️ 批量私信」；客户池「🥱 批量标沉睡」。串行执行（沿用灌水机器人队列 + 拟人间隔）。

### 6.7 防反爬约束（沿用 v1）
复用 `delay_config`：每日私信上限（默认 20）、批量间隔随机 30~90s、每人 `funnel.dmCount≤3` 后置灰、发送前检测私信限制提示→标无效并提示改评论破冰、话术强制个性化。新增档位 `dmOpenWait / dmTypingDelay / dmSendGap`。

## 八、v1 → v2 数据迁移（重要，不改会脏）

现有 `prospect_list` 存量结构（`dmStatus`/`customerStatus`/`isLiker`/`origin`）需**一次性**归并到新结构，读取时做惰性迁移：

| v1 字段 | 迁移到 |
|---|---|
| `dmStatus` | → `funnel.step`：`pending→pending`、`sent→touched`、`replied→replied`、`converted→closed`（同时 `stage=customer`）、`invalid→pending + affinity 降级提示` |
| `customerStatus` | → `account.status`：`intent/sales→maintain`、`after_sale→after_sale`、`dormant→dormant`；凡有 `customerStatus` 的 → `stage=customer` |
| `isLiker / origin==='点赞' / keywordHit==='__liker__'` | → `stage=lead`、`stageEntry='点赞'` |
| `origin` | → `stageEntry`（映射表见 3.3），origin 字段废弃 |
| `intentLevel` | → `affinity.intentLevel`（仅排序） |

迁移实现：在 `Storage.getProspectList()` 读出口做一次性 `_migrateOldProspect(p)`，命中旧字段即转换后落库，之后永久是新结构。迁移必须是**幂等**的，不重复执行。

## 十二、风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| 私信 DOM 未知（陌生人限制） | 🔴 高 | 阶段 0 勘探；不过则私信自动化降级为「打开主页+人工发」 |

| 数据量增长（几千人） | 🟢 低 | 按 tenant 分 key + 分页（每页 50） |
