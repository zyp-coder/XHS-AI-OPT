# 后台分平台状态与暂停 · 确认单（2026-10-25）

> 需求原话：「我没在哪里可以看到能区分抖音跟小红书的获客……你在服务端应该是有一个控制的地方的吧」
> 查系统后的结论：服务端现在只有「绑号」是分平台的；获客这条链只在小红书跑。这轮把后台两平台的状态摆清，并给小红书获客／抖音发笔记各一个暂停开关。

## ✅ 已定（全部按推荐）

| # | 事项 | 定法 |

## 📌 替你按默认定的（扫一眼）

1. **双平台同发的一篇**：暂停抖音时，这篇只发小红书；恢复后只补发抖音（系统已有「只补没成的」，不会重复发小红书）。
2. **搜索链跑到一半按暂停**：当前那一类跑完就停住，不判失败；恢复后从下一类接着跑。
3. **两格的「最近一次活」只显示各自主活**：小红书格只显示获客/日常浏览，抖音格只显示发笔记；AI客服、整页发送不挤进这两格。
4. **暂停不改客户看到的字**：只加那一行灰字，客户其他按钮、文案不动。
5. **页面最宽从 1080 放到 1320**：两格加进来后原宽度会横向滚动，看不到抖音那格；放宽后两格同屏。其他签只是变宽，内容不动。

## 🚫 明确不做

- 不做抖音获客（搜词/评论区/私信）；这轮只做状态和开关。
- 不做按平台的全站总闸；现有「熔断」不动。
- 不改执行器（暂停全在服务器拦住，执行器收不到单）。
- 不整份覆盖 `web/popup.js`；只动 `web/exec-bridge.js` 的横幅一处。
- 不把 AI客服、整页发送的状态摆进两格。

## 实现落点

| 文件 | 动什么 |
| --- | --- |
| `server/exec-channel.mjs` | 账号加 `platform_pause`；`platformOf` 复用；`placeOrder` 在档位/绑号闸之后加暂停闸（网页手点与定时自动派同一条）；`/api/exec/orders` 带出 `pause` |
| `server/exec-sched.mjs` | 搜索链/队列自动跑遇到暂停：不判失败、不写「done」，下一分钟再看；发笔记把暂停的平台从本轮剔除（全暂停就整条等） |
| `server/dev-server.mjs` | `/api/admin/accounts` 每行带 `platformPause`＋每平台最近一单；新增 `/api/admin/platform-pause`（带后台口令） |
| `web/admin.html` | 两格改成分平台卡片：状态行＋最近一单＋暂停/恢复；表尾说明补两句 |
| `web/exec-bridge.js` | 顶栏灰字横幅（读 `orders.pause`），不弹红 |

## 上线顺序

1. 本机起服务，造 5 种状态（正常/暂停/错号/离线/没跑过）自检并截图。
2. 推公网 → 重启 `xhs-demo`（**重启要老板单独一句确认**）。
3. 老板在公网后台点一次暂停/恢复，再到客户网页看一眼灰字横幅。

## 风险与回滚

- 新字段 `platform_pause` 老数据没有＝默认不暂停；出问题删字段即回到现在。
- 暂停闸在 `placeOrder` 里，是纯新增分支；不动现有档位闸、绑号闸、版本闸。
- 定时轮遇到暂停必须「静默跳过」，别每分钟刷日志——自检里专门看流水。
- 发布/获客的真动作链不改，只改「派不派」；回滚只改服务器，执行器不用重装。
