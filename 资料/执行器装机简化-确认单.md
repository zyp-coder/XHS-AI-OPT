# 执行器装机简化 · 确认单（2026-10-26 定稿：走 A 轨）

**要解决的事：** 客户装执行器原来要「下载 → 解压到固定文件夹 → 开开发者模式 → 加载解压扩展 → 填配对号」五步，客户容易卡在中间；而且一个包全网通用，所有客户同一份东西。

**老板圈的三条：**
1. **不要一份包通用**——每个客户一份自己的包、自己的身份。
2. 对「官方开关（由组织管理）」有戒心。
3. 真机试过 B 轨之后定：**不做零点击，回到两下点击**（走 A 轨）。

**本单结论：** A 轨已按下面这套落地。B 轨（官方开关静默装）**不做**，原因写在第四节——不是不想省客户那两下，是那条路在现有条件下真走不通。

---

## 一、客户现在走几步（原来）

| 步 | 原来 | 卡点 |
|---|---|---|
| 1 | 网页点下载 zip | 一般没事 |
| 2 | 解压到固定文件夹，且以后不许挪 | 有人解压到桌面、有人挪文件夹 → 扩展立刻失效 |
| 3 | 打开 edge://extensions，开「开发者模式」 | 一半人找不到开关 |
| 4 | 点「加载解压缩的扩展」，选中文件夹 | 选错层级（选了上一级或里面一层） |
| 5 | 打开面板填配对号 → 挂上 | 抄错码、漏一位 |
| 6 | Edge 过几次重启把开发者扩展偷偷禁用 | 靠 `Edge-防禁用.bat` 补，客户基本不会自己用 |

---

## 二、现在走几步（已落地）

1. 网页点「下载我的安装包」（这个号专属的那份，配对号已在包里）
2. 解压 → 双击「装我.bat」→ 弹「Windows 已保护你的电脑」就点「更多信息」→「仍要运行」
   - 它自己把文件放到 `%LOCALAPPDATA%\XhsHand\<账号 id>\`（固定位置、客户不用选、也不容易挪）
   - 它自己打开扩展页，并把要选的文件夹路径复制到剪贴板
   - 屏幕上留一份「装机-看这里.txt」，写着下面两下怎么做
3. 扩展页里两下：开「开发者模式」→「加载解压缩的扩展程序」→ 在选文件夹的窗口按 Ctrl+V → 选择文件夹
4. 点工具栏上的执行器图标 → 配对号已经填好 → 点「挂上」→ 变「🟢 在线待命」

比原来省掉的：**解压位置由脚本定、配对号不用抄、扩展页自动打开、路径自动进剪贴板**。

## 三、A 轨实际怎么做的

### 客户代号＝账号 id
- 每个客户包的文件名、安装文件夹都用**账号 id**（`acc_` 打头那串），不另造一套编号。
- 扩展身份跟安装文件夹路径走 → 账号 id 不同，扩展身份就不同，天然一人一个，不存在「一份包全网通用」。
- 服务器不用改：后台账号列表和 `/api/auth/me` 本来就把 id 发给网页了。

### 包在哪、包里多什么
- 出包：`node executor/pack.js --slug=<账号 id> --name="<客户称呼>" --code=<配对号>` → 产出 `web/download/customers/<账号 id>.zip`（旁边还落一份同名 `.json` 记着配对号和版本）
- 包里比通用包多四样：`prefill.json`（配对号/服务器地址）、`装我.bat`、`更新.bat`、`卸载.bat`、`装机-看这里.txt`
- 通用包 `/download/executor.zip` 留着自测用，不再发给客户

### 网页改了哪几处
| 文件 | 动什么 |
|---|---|
| `web/setup.html` | 改成「四步」；下载按钮自动指向本账号的专属包（先探一下有没有，没有就退通用包并在页面上说一声）；每一步补「✓ 看到什么算对」；写明「只能用 Chrome 或 Edge」、SmartScreen 怎么点；常见问题按新四步重写；顶部与常见问题都链到图文教程 |
| `web/tutorial.html`（新） | 图文教程一页：四步各配一张示意图（扩展页开关位置、选文件夹、面板已填好）、每步「做什么／看到什么算对／卡住看哪条」；六个卡点；装完怎么验；掉线/换电脑/卸载/更新。同一份文件以「装机教程.html」打进客户包，离线也能看（打开时自动藏掉跳回网页的链接） |
| `web/admin.html` | 「复制装机消息」改成「先登录 → 然后四步」五段式（编号与网页一致），末尾附教程链接；探到专属包就给下载链接，探不到就提醒你另发 zip；账号行菜单加一个「打包命令」 |
| `web/guide.html` | 引导页里「装执行器（三步）」改成四步，路线那句补上「点挂上」，加教程链接 |
| `web/account.html` | 页尾「装执行器（三步）」→「（四步）」，加教程链接 |
| `web/executor.html` | 第三步改成「双击装我.bat，点挂上」，加教程链接 |
| `web/popup.html` | 顶栏那个「装执行器（三步）」提示文字改四步 |
| `executor/pack.js` | 包内说明改成与网页同编号的四步；把 `web/tutorial.html` 复制成包里的「装机教程.html」 |
| `scripts/hand-package-gate.js` | 允许清单加「装机教程.html」 |

### 防禁用
- 统一口径：**客户用 Chrome 或 Edge**（360、QQ、搜狗这些装不了）。
- Edge 会偷偷禁用开发者扩展，`Edge-防禁用.bat` 留在装好的文件夹里兜底，但不再当主路。

## 四、B 轨为什么不做了（真机验过）

原来想的是：双击一个 bat → 写一条浏览器「强制安装扩展」的设置 → 浏览器自己装上，客户连开发者模式都不用碰。

真机验下来三条硬墙：

1. **官方开关只认 https 的更新地址**。我们服务器现在是裸 IP 的 http，设置写进去浏览器一句不抱怨，但一条请求都不发——装上不了。要走就得给服务器配域名＋证书。
2. **Edge 不认本地 crx 文件**。退一步想让它读本机已有的包，注册表那条路写了也没反应。
3. **本机的策略区要管理员权限**才能写。客户电脑上未必有。

结论：**这条路的成本是「域名＋证书＋每台机器可能要管理员」，省下的只是客户点两下。** 不划算，这轮不做。真到有客户明确说「我不想自己点」，再单独立项。

## 五、升级与卸载

| 场景 | 现在怎么走 |
|---|---|
| 我们发新版 | 重新打这个客户的包 → 客户下新的 → 双击「更新.bat」（覆盖文件、配对号不动）→ 扩展页点一下「重新加载」 |
| 客户换电脑 | 新电脑用同一个配对号，出一份新包照装；旧机自动下线 |
| 客户要退 | 双击「卸载.bat」（删文件夹）＋ 扩展页点移除 |
| 我们想全停 | 服务器熔断（现有机制，没动） |

> `更新.bat` 覆盖的是同一个安装文件夹，所以扩展身份不变、配对号不掉。

## 六、明确不做（这轮）

- 不做官方开关静默装（理由见第四节）。
- 不上架应用商店。
- 不做免登录、不改客户浏览器首页/搜索。
- 不动执行器干活逻辑、不动服务器派活闸门（纯装机与分发）。
- 不引入签名钥匙——A 轨的扩展身份由安装路径决定，用不上钥匙。
