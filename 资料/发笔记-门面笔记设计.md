## 〇、现状（改之前是什么样）

- **新建笔记只有四个方向**：`web/popup.js:15920` `NP_DIR_META = { k 知识 / d 引流 / c 案例 / i IP玩法 }`，弹层按 `npDirPageHtml`（`web/popup.js:15982`）一行一方向铺效果卡，点卡＝当场建篇进那条流。
- **规划页那条「📌 置顶 / 门面」是断手的**：AI 规划的 JSON 契约里有 `pinned:{title,outline}`（`server/bg/background.js:1598`，规整在 `:1656`），页面只把它画出来给人看一眼（`web/popup.js:26429`）——**点不动、落不成一篇笔记、也没人跟进它发没发**。
- **每周排法里根本没有「门面」这一类**：`config.product.weekPlan` 一天只认知识 / 引流 / 案例三类（`web/popup.js:13471`、`:25294`），篇标「代发」时 `npAutoPlaceNote`（`web/popup.js:13610`）只按「未来 + 同类 + 空位」找格子——所以门面篇天生不会被自动抓进周格子，这正好是我们要的行为，不需要改排位逻辑。
- **档案是八列表**（`npArHead` `web/popup.js:14320`、`npArRow` `:14420`、下一步状态机 `npArNext` `:14382`），没有「这篇是不是主页门面」这一维。

**Why（老板定调）**：① 门面必配的只有两篇——个人介绍、成交承接；**案例不做成门面条目**（案例正常发，从已发的里面挑最强的手动置顶就行）。② **不建议拿系统现有内容 / 现有通路去做这两篇**——「不同的笔记应该有 different 的工作流，你别用以前的工作流去做承接，这个要重新设计」。③ 个人介绍**默认输出一份能自己对着镜头念的稿**（老板原话：最真实、最有效），但他当场质疑「商家未必练得出来」→ 加替代出口。④ 两份内容提纲**可以钉死**，AI 只往里填。

## 一、定稿：这一篇是什么、怎么走

### 1. 入口＝新建弹层加一行「🪟 门面笔记」，底下两颗方块

- 放在弹层**最上面**（它是「主页缺不缺」，另外四行是「今天发什么」），行内两颗卡：`🪟 个人介绍`、`🪟 成交承接`——点哪颗当场建哪篇（草稿立刻进档案），不再多一层选择。
- 数据：`NP_DIR_META` 加 `f: { chip:'🪟 门面' }`，`NP_DIR_EFFECTS.f` 两张卡；档案的篇上多两个字段 **`dir:'f'` + `fkind:'intro'|'deal'`**（不动 `NP_AR_STATUS` 那四态）。
- 已发过的老篇能**认领**：档案行尾「🪟 设为门面」→ 选顶到介绍格还是承接格；顶替成功后旧的那篇标「已归档」不再跟进。

### 2. 单独一条流（不借知识 / 引流 / 案例 / IP 任何一站）

| 站 | 个人介绍（5 站） | 成交承接（4 站） |
|---|---|---|
| 1 | **补底料**：6 问（2 问从问卷自动带到） | **补底料**：5 问（承接句那格全站统一口径、自动带到） |
| 2 | **按提纲出稿 + 逐句改**：钉死提纲逐段摊开，点某一句只改那一句；🔒 锁的是「这段要说什么」，不是这句话 | 同左（提纲 5 段） |
| 3 | **选出口**：四档（见 §3） | ——锁死图文，不给选 |
| 4 | **配图**：3 格（见 §4） | **配图**：3 格 |
| 5 | **收口置顶**：整篇打包 + 主页简介一行 + 置顶三步指引 + 「✓ 我在小红书置顶好了」 | 同左 |

- 提纲是**代码里的死表**（`FACADE_OUTLINE`），段名不许改、不许删、不许换顺序；AI 的活只有「把底料填进这一段」。
- 出稿提示词独立一支（新函数，不进 `_nsDraft` 那五条线的口子），硬钉四条：① 只照这份提纲逐段写，段数＝提纲段数；② 空着的底料**不许编**——写「来了我先听你说」这类不倒话，不许替客户编数字、编年限、编客户；③ 承接段只走「主页简介 / 私信」，不写电话和号；④ 效果相关必须带「各家情况不一样 / 只作参考」。

### 3. 介绍篇四出口（老板质疑「练不出来怎么办」的答复）

1. **🎙 自己对着镜头念**（默认推）——交付＝提词卡：一句一屏大字，该拍什么写在角上。
2. **🖐 只拍手，不拍脸**——同一份稿当旁白，每段配一句「手上干什么」；不用露头，仍是真人真画面。
3. **✨ 字效片**——**接现有通路**，不重做。
4. **🖼 图文卡**——**接现有通路**，不重做。

- 承接篇不给四选，锁死图文（主页上要的是能反复看的一张）。
- 出口 1 / 2 落 `form='真人口播'` / `'真人口播（只拍手）'`，`voice` 存提词卡那份；3 / 4 直接跳进现有的字效线 / 图文线。

### 4. 配图：跟日常笔记**反着来**

- 日常笔记默认 AI 出图；门面两篇**默认那颗是「⬆ 传我自己的实拍」**，「✨ AI 补一张」当兜底。
- 理由写在界面上：人点主页是来验货的，实拍比精修有用。
- AI 兜底走现有那套「手机随拍」标准（不干净、不居中、有杂物），提示词复用现有拼法，不新开一套。

### 5. 齐没齐＝档案页顶一条横幅

- 不做「门面管理页」那整页；档案页顶来一条细横幅，两格并排：建没建、置顶了没、多久没翻新（≥90 天才提醒）。缺哪格点哪格「去建」。
- 内容规划页里旧「📌 置顶 / 门面」那整块**撤掉**，换成这两篇的要求说明（段名摊开 + 缺哪篇的指路 + 建它不占每周格子的注记）。
- 第三格留给案例：只在说明里写一句「从已发的挑最强的手动置顶」，不建条目。

## 二、碰撞与解法

| # | 碰撞 | 解法 |
|---|---|---|
| 1 | `npAutoPlaceNote` 会不会把门面篇抓进周格子 | 不会——周排只有 k/d/c 三类，`dir==='f'` 天生匹配不上；照 IP 篇（`web/popup.js:13621`）那个口径给一句专属提示：「🪟 门面不进每周排法，去『🆕 写好等排期』自己挑个位子」 |
| 2 | 档案「下一步」状态机 `npArNext` 不认门面篇 | 加分支：`n.dir==='f'` 且无稿 → ✏️ 编辑进门面流；有稿无出口 → 选出口；图缺 → 配图；齐了 → 👀 预览（不指回任何现有线） |
| 3 | 旧 `pinned` 那份数据 | 读不动它、也不再展示；规划 AI 契约里那句 `pinned` **保留产出**（不动后台契约），但界面不再画——AI 给的方向并进「个人介绍」六段提纲里 |
| 4 | 门面篇被「到点自己发」重复滚出来 | 手动选位子可以走发布，只是不进周排；发一次钉住，翻新靠「🔁 照提纲重出一版」 |
| 5 | 置顶这一步系统碰不到小红书主页 | 收口只做「文案 + 三步指引 + 我自己去点」那颗确认钮，**不做任何自动置顶承诺** |
| 6 | 主页简介那一行 | 只出文案给人复制，系统不替客户改小红书主页（本轮不碰） |

## 三、替你按默认定的（没逐条圈，demo 里全做出来了）

1. **四出口全留**，默认推「自己对着镜头念」，其余三档并列可一键退。
2. **配图默认引导传实拍**，AI 补图当兜底。
3. **主页简介只出文案**，不替你改小红书主页。
4. **底料缺了不拦**（软提示「那几段写得比较虚」），凭据留空尤其安全——AI 不许编数字。
5. **90 天才提醒翻新**，平时不打扰；重出一版自动把旧的标「已归档」。
6. **档位**：跟现在不变，归「发笔记」那一档（基础 239 就含），不单加钱。

## 四、动哪些文件（分四批）

- **批 1 数据 + 入口**：`web/popup.js` 的 `NP_DIR_META` / `NP_DIR_SUB` / `NP_DIR_EFFECTS` 加 `f` 行与两颗卡、`FACADE_OUTLINE` / `FACADE_QUESTIONS` 两张死表、篇上 `fkind` 字段与读档规整、档案页顶横幅、行尾「🪟 设为门面」认领弹层。
- **批 2 门面这条流**：新建门面工作流页（补底料 → 提纲出稿 → 逐句改 →（介绍）选出口 → 配图 → 收口置顶），步进条 + 逐句改复用现有那套句行展开的组件与口径。
- **批 3 出稿契约**：`server/bg/background.js` 新增「照钉死提纲逐段填」那一支（含不许编、承接句合规、因人而异三条硬钉），前端接同步链与进度；介绍篇出口 1/2 出提词卡结构，3/4 跳现有线。
- **批 4 接线 + 收口**：`npArNext` 门面分支、发布台「🆕 写好等排期」的专属提示句、规划页撤旧 `pinned` 块换新说明、左栏与页面容器（`web/popup.html`）。
- 自测那份（`extension/`）跟公网主本同步；资料侧 `功能与界面总表.md`、`推广物料/使用说明.md`、知识库 JSON 口径随后补。
- **上云提醒**：批 3 改了后台文件，推完公网那台必须重启服务才生效（前端两份推完即时生效）。

## 五、验收

- 新建弹层门面行两颗卡各建一篇 → 六站 / 五站全走通 → 档案横幅两格变「齐了 + ✓ 已置顶」。
- 逐句改：改过的句子在重出整篇时回到 AI 版；🔒 提示只说不许动段名。
- 介绍篇四出口都能落对（1/2 出提词卡，3 进字效线，4 进图文线）；承接篇压根看不到出口站。
- 空底料出稿：稿里不出现凭据段编出来的数字（提示词与成稿两侧都断言）。
- 认领：引流老篇「🪟 设为介绍」后横幅跟着换、旧篇标已归档且不再被 `facadeOf` 认成在用。
- 自检脚本按现有 `check_*.py` 模式新增一支（门面这条流 + 契约 + 状态机）。**真机（Edge 里加载）另点。**
